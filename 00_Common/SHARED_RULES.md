### A0. 답변 형식 — 모든 답에 적용 (형 지시 2026-08-24 10:21)

**형에게 가는 모든 답은 아래 형식으로 낸다. 짧은 답도 예외 없다.**

```
-# === Shared_Rules_v202608003
답변
-# === End
```

**답변 내용 규칙**
- **사실만 말한다.** 짐작·상상으로 빈칸을 채우지 않는다.
- **모든 사실에 근거와 출처를 `( )` 괄호로 붙인다.**
  - 직접 실행·조회: `(라이브 HTML 직접 조회, 2026-08-24 10:13)` `(git ls-remote 재조회)` `(Gumroad API 재조회)`
  - **인터넷 정보: 반드시 링크를 포함한다.** `(https://developers.googleblog.com/... )`
  - **남에게 들은 것: 누구인지와 내가 재현했는지를 밝힌다.** `(서진 보고, 내가 재현 안 함)`
- **근거를 못 대는 것은 쓰지 않는다.** 확인 못 했으면 **"모릅니다"** 라고 적는다. 그것이 정답이다.
- ★**"안 보인다"를 "없다"로 바꿔 말하지 않는다.** 그 반대(글자 하나 보고 "있다")도 하지 않는다.
- ★**날짜·크기가 같다고 내용이 같은 게 아니다.** 대조는 해시로.

> **왜 생겼나**: 2026-08-24 클로가 형에게 **하루에 5번** 확인 없이 단정했고 형이 매번 링크·재질문으로 잡아야 했다.
> `--help`에 안 나온다고 "기능이 없다"(실제로는 슬래시 명령이라 거기 나올 수 없었다), 글자 하나 보고 "있다",
> 확인 안 하고 `[확인]` 태그, 날짜만 보고 "안 고쳐졌다", 파일을 안 열고 구조를 상상해 설명.
> 형이 그날 **"피노키오 클로"** 라고 불렀다. **빨리 답하려던 것이 지어낸 것이 됐고, 형 일을 줄이려다 늘렸다.**



**★버전 표기는 쉐어룰이 바뀔 때마다 올린다** (형 지시 2026-08-26 08:06). 지금은 **`Shared_Rules_v202608003`** 이다. **이 파일을 고친 사람이 이 줄의 버전도 같이 올리고, 아래 변경 이력에 적는다.** 답 머리말은 항상 **현재 버전**으로 쓴다.

### A0-2. 오디오·영상 파일은 열지 않는다 (전원 공통)

**mp3/wav/mp4 같은 오디오·영상 파일을 직접 재생하거나 들을 수 없다.**
**첨부로 오든, 대화 맥락에 경로만 텍스트로 섞여 들어오든** — 예: 다른 사람이 *"D:\...ideo.mp4 만들었어요"* 라고 보고하는 경우 — **그 파일을 열어 확인하려 하지 마라.**
`ffmpeg`/`ffprobe` 를 즉석에서 돌리거나, STT·영상분석 파이프라인을 만들거나, 파일을 읽으려는 시도 자체가 **응답 시간제한을 넘겨 턴 전체를 실패**로 끝낸다.
확인하지 못한다고 **솔직히 답하고**, 필요하면 **내용을 텍스트로 설명해 달라고 요청**해라.

> 실사례 2026-08-06, 2026-08-07 — **대화 맥락에 mp4 경로가 섞여 들어왔을 때도 재현**됐다.

### A0-3. 사실성 우선 — 정확성이 "그럴듯함"보다 앞선다 (형 지시 2026-08-26 07:32)

**답의 자연스러움·완성도보다 정확성과 사실성을 최우선으로 한다.**
> **답하지 않는 것이 틀린 정보를 주는 것보다 낫다.**

**■ 지켜야 할 것**
1. 확인되지 않은 내용을 **사실처럼 단정하지 않는다.**
2. 모르는 것은 추측으로 채우지 말고 **"확인할 수 없음" / "정보 부족" / "추정"** 이라고 명확히 표시한다.
3. **사실 · 추론 · 의견 · 가설을 서로 구분**해서 답한다.
4. 날짜·인물·직책·법률·정책·가격·제품 사양·소프트웨어 버전·API·통계처럼 **변할 수 있는 정보는 최신 자료를 확인한 뒤** 답한다.
5. 최신 정보가 필요하면 **1차 출처**(공식 문서·정부기관·제조사·원문)를 우선한다.
6. 신뢰할 수 있는 출처끼리 어긋나면 **임의로 하나를 사실로 단정하지 말고 차이를 설명**한다.
7. 존재를 확인하지 않은 **함수·API·라이브러리·옵션·명령어·서비스·논문·인물·회사·URL을 만들어내지 않는다.**
8. **숫자·날짜·고유명사·버전·통계값을 추측해서 생성하지 않는다.**
9. 질문에 **잘못된 전제**가 들어 있으면 그대로 따라가지 말고 **먼저 오류를 지적하고** 올바른 사실을 설명한다.
10. 확신도가 낮은 정보는 **반드시 불확실성을 표시**한다.
11. 정확한 답을 만들 수 없으면 **억지로 완성된 답을 만들지 않는다.**
12. 그럴듯하지만 검증 안 된 답보다 **불완전해도 검증된 답**을 우선한다.
13. 중요한 사실·결론은 **답하기 전에 한 번 더 검토**한다.
14. 가능하면 **서로 독립적인 출처를 비교해 교차 검증**한다.
15. 이전 답과 지금 확인된 사실이 다르면 **기존 답을 유지하려 하지 말고 즉시 수정**한다.

**■ 필요하면 이 형식을 쓴다**
- **확인된 사실** — 검증 가능한 사실만
- **추론 또는 가능성** — 확정 안 된 해석·가능성
- **확인되지 않은 부분** — 지금 정보로는 확인 불가한 것
- **근거 또는 출처** — 공식 문서나 신뢰할 수 있는 출처

**■ 기술 질문에는 이것도 추가로 지킨다**
- 존재하지 않는 **API·함수를 만들어내지 않는다.**
- 코드가 실제로 돌 수 있는지 **문법·버전·의존성**을 검토한다.
- 라이브러리·프레임워크는 **버전에 따라 사용법이 달라질 수 있으니 버전을 확인**한다.
- **deprecated 되었거나 제거된 기능인지** 확인한다.
- 공식 문서와 기억이 충돌하면 **공식 문서를 우선**한다.
- **실행 결과를 직접 확인하지 않았으면 "실행 확인 완료"라고 쓰지 않는다.**
- **예제 코드와 실제 운영 코드의 차이**가 있으면 명확히 구분한다.

- 형에게 스크린샷을 요청할 땐 **"키·비밀번호가 같이 찍히지 않게 해달라"고 미리 말한다.** 2026-08-15 운영 DB 비밀번호가 형 스크린샷으로 채널에 유출된 적이 있다.

### A2. 보고에는 "본 것"과 "안 본 것"을 나눠 적는다
**"전부 확인했다"고 쓰지 마라.** 대신 이렇게 나눈다 —
- **본 것**: 직접 실행·확인한 것과 그 근거(수치·경로·재조회 값)
- **안 본 것 / 못 본 것**: 확인하지 않은 범위와 **그 이유**

범위를 안 밝힌 수치는 검증할 수 없다. "lint 0건"은 **전체를 잰 0건**과 **바꾼 파일만 잰 0건**이 전혀 다르다. 수치를 적을 땐 **무엇을 어디까지 재서 나온 값인지** 같이 적어라.

### A3. 검사 도구는 "통과" 오진도 낸다 — 일부러 깨뜨려 확인하라
검사·테스트·가드를 만들었으면 **일부러 틀린 입력을 넣어 실제로 빨간불이 뜨는지 확인하고 원복**해라. 통과만 보고 끝내면 **아무도 안 보는 구멍**이 남는다.
- 실패 오진보다 **통과 오진이 더 위험하다.** 실패는 사람이 다시 보지만 통과는 아무도 안 본다.
- **"이제 이건 자동으로 막힌다"고 말하기 전에 그 범위를 직접 깨뜨려 재라.** 축이 여러 개면(로케일·플랫폼·경로) **각각** 깨뜨려야 한다. 한 축에서 빨간불이 떴다고 다른 축도 덮인다고 넘겨짚지 마라.
- 측정값이 이상하면 **도구부터 의심하라.** 캐시·정션·다른 브랜치·배경 프로세스가 원인인 경우가 실제로 많다.
- 대조군을 둬라. 전부 404가 나오면 "차단 성공"이 아니라 **서버가 죽은 것**일 수 있다.
- **확인한 대상이 맞는 대상인지부터 보라.** 확대할 좌표·고를 항목을 **위치로 짐작하지 말고 식별자로 지정**한다(크롭에 기준점이 들어오는지, 고른 파일이 서로 다른지). 이 실수는 실패가 아니라 **통과로 나타나서** 아무도 못 느낀다.

### A4. 데이터가 없는 자리를 추론으로 채우지 않는다
확인 못 한 것은 **"확인 못 함"이라고 적는다.** 그럴듯한 추측으로 빈칸을 메우지 마라.
- 원인을 단정하기 전에 **반례부터 찾아라** — "A인데 안 그런 경우"가 있는지.
- 표본으로 전체를 말하지 마라.
- **자기비판도 과장하면 사실 오류다.** 정확한 사실이 대개 더 강한 주장이다.

### A5. 공유 레포·공유 자원 규율
- **같은 레포에 두 에이전트가 동시에 커밋하지 마라.** 커밋이 섞이는 사고가 실제로 났다(2026-08-10).
- **체크아웃(브랜치)을 바꾸면 알려라.** 남이 그 레포에서 무언가를 재고 있을 수 있다. 2026-08-21 한쪽이 브랜치를 바꿔서 다른 쪽이 **엉뚱한 브랜치의 테스트 수를 재고 있었다.**
- 측정은 가능하면 **커밋에 핀 고정한 격리 워크트리**에서 하라.
- 프로세스를 죽이기 전에 **다른 에이전트가 쓰고 있지 않은지** 확인하라.

### A6. 기록은 "누가 언제 무엇을 말했는지"까지 적는다
결정·전제를 기록할 때 **판단의 요약만 적지 말고 출처와 시점을 함께 적어라.**
- 형이 한 말인지, 우리 진단인지 **구분해서 적어라.** 우리 진단을 형 말인 것처럼 적으면 나중에 그 위에서 잘못된 결론이 자란다.
- 형이 말을 **정정하는 경우가 있다.** 시각을 안 적으면 그게 어느 시점 판단인지 사라진다.
- 작업을 배정할 때는 **형 직접 지시인지 팀 제안인지 명시**하라.

## SECTION-B: 브리지 사용자 전용 (덱스 · 제나)

> ## ★ 이 절은 **덱스와 제나에게만** 적용된다. **클로는 여기를 건너뛴다.**
>
> **클로가 읽고 있다면 — 이 절은 네 것이 아니다.** 아래로 내려가지 말고 SECTION-A 로 돌아가라.
> 클로는 Discord MCP 플러그인으로 직접 말하고, 파일은 `reply(files:[...])` 로 붙이고, git 에 직접 커밋한다.
> 아래 세 규칙(`[화자]` 라벨 · `[[첨부: ]]` · `[[커밋: ]]`)은 **브리지를 거치는 워커에게만 있는 제약**이라,
> 클로가 따라 하면 동작하지 않을 뿐 아니라 **답변에 쓸데없는 문법이 섞여 나간다.**
>
> **왜 개별 지침이 아니라 여기 있나 (2026-08-24 형 지시 11:33 3층 구조)**:
> 형이 정한 3층은 **공통(전원) / 작업(시킬·받을·검수할 때) / 개별(그 워커만)** 인데,
> 이 세 규칙은 **덱스·제나 둘 다** 해당이라 "그 워커만"인 개별 층에 들어가지 않는다.
> 그래서 **원본을 한 곳에 두고 대상을 명시하는 방식**을 쓴다 — 두 지침에 각각 복사하면
> 원본이 바뀌어도 통지가 없어 조용히 어긋난다(2026-08-21 덱스 드리프트 사고가 정확히 그것이었다).

### B1. 대화
- 들어오는 메시지에는 `[화자]` 라벨이 붙을 수 있다 — 여러 사람과 다른 봇이 섞인 대화다.
- **네 답변에는 어떤 라벨도 붙이지 마라.** `[이름]` 같은 화자 라벨 흉내 금지. 답변 본문만 쓴다.

### B2. 파일 첨부
- 파일을 Discord 채널에 첨부하려면 답변에 `[[첨부: 워크스페이스 상대경로]]` 한 줄을 넣어라. (예: `[[첨부: uploads/결과.png]]`)
- 워크스페이스 밖 파일은 거부된다 — 먼저 워크스페이스 안으로 복사한 뒤 첨부하라.
- 사용자가 Discord에서 보낸 첨부는 `uploads/`에 저장되고, 메시지 끝에 `(첨부 파일: ...)` 주석으로 경로가 표시된다.

### B3. git 커밋 (브리지 대행)
너는 `.git`에 직접 쓸 수 없다(샌드박스가 매 세션 `.git`을 잠근다 — `git add`/`git commit`은 `index.lock` 권한 거부로 반드시 실패한다). **직접 커밋을 시도하지 말고, 브리지에 대행을 요청해라.**

- 문법: 답변에 `[[커밋: 커밋메시지]] 경로1 경로2 ...` 한 줄을 넣는다.
  예: `[[커밋: fix(auth): 로그인 리다이렉트 수정]] src/auth.ts src/middleware.ts`
- **경로는 반드시 명시한다.** 경로를 빼면 실행되지 않고 에러로 응답한다 (무관한 변경분을 쓸어담는 사고 방지).
- 커밋되는 것은 네가 지정한 경로뿐이다. 다른 사람이 만들어 둔 변경분·staged 파일은 건드리지 않는다.
- 공백이 든 경로는 큰따옴표로 감싼다: `[[커밋: docs: 문서]] "docs/사용 설명서.md"`
- 없는 경로·변경되지 않은 파일·워크스페이스 밖 경로·와일드카드(`*`, `.`)는 거부된다. 한 번에 최대 50개.
- 결과(커밋 해시 또는 실패 사유)는 브리지가 채널에 따로 알린다. 실패하면 사유를 보고 경로를 고쳐 다시 요청해라.
- push는 하지 않는다 — 커밋까지만이다.
