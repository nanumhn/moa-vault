# 업무 체크리스트 — 시킬 때 / 할 때 / 검수할 때

> **왜 있나 (2026-08-21 형 지시).** 형이 이렇게 말했다 —
> *"룰을 생성해 둬도 그거를 잘 안 지켜서 자꾸 문제가 생기고, 업무를 시키면 검수를 다 거치고 나서
> 반영을 해야 되는데 그런 것도 지키지 않고, 이러니까 자꾸 재검하고 재검하고. 이러다 보니 더 시간이
> 많이 걸리는 것 같아."*
>
> **진단**: 그날 검수가 다섯 번 무효화됐는데 **아무도 규칙을 안 어겼다.** 검수 중에 나온 지적을
> 즉시 반영하니 검수 결과가 매번 죽는 구조였다. **사람을 다그쳐서 안 고쳐지고 순서를 바꿔야 고쳐진다.**
>
> **원칙**: 규칙은 **읽는 자리**가 아니라 **쓰는 자리**에 있어야 지켜진다.
> 그래서 이 체크리스트는 **일을 시작하기 전에** 지시서에 박아 넣는다. 다 만든 뒤에 꺼내면 늦다.
> (실측: 2026-08-21 시우에게 검사 구역과 보고 형식을 지시서에 미리 넣었더니 **반려가 0회**였다.)

---

## 1. 시킬 때 — 지시서에 반드시 넣을 것 (6개)

| # | 항목 | 왜 |
|---|---|---|
| 1 | **지시 출처** — 형 직접 지시인지 팀 제안인지. 형 말이면 **원문 그대로 + 시각** | 우리 진단을 형 말인 것처럼 전하면 그 위에서 잘못된 결론이 자란다. 형은 말을 정정하기도 한다 |
| 2 | **완료 기준** — 무엇이 되면 끝인가. 수치·재조회 값으로 | "잘 만들어라"는 완료 판정이 불가능하다 |
| 3 | **검사 항목** — 이 종류 산출물에서 **과거에 실제로 터진 것** | 일반론 말고 실제 사고 목록. 이걸 미리 주면 애초에 안 걸린다 |
| 4 | **하지 말 것** — 범위 밖, 건드리면 안 되는 파일·브랜치, 커밋 금지 여부 | 범위를 안 적으면 넓게 해석해서 남의 작업을 밟는다 |
| 5 | **막혔을 때 규칙** — 몇 번 시도하고 올릴 것인지 | "조금만 더 하면 될 것 같다"로 시간이 샌다. 상한을 숫자로 준다 |
| 6 | **보고 형식** — "본 것 / 안 본 것"으로 나눠 적을 것 | 형식을 안 주면 좋은 소식만 온다 |

## 2. 할 때 — 보고에 반드시 넣을 것 (6개)

| # | 항목 | 왜 |
|---|---|---|
| 1 | **본 것** — 직접 실행·확인한 것과 근거(수치·경로·**재조회 값**) | 성공 메시지는 근거가 아니다. 다시 조회한 값만 근거다 |
| 2 | **안 본 것 / 못 본 것 + 이유** | **"전부 확인했다"고 쓰지 마라.** 안 본 자리가 본 것처럼 통과한다 |
| 3 | **측정값의 범위** — 무엇을 어디까지 재서 나온 값인지 | "lint 0건"은 전체를 잰 0건과 바꾼 파일만 잰 0건이 전혀 다르다 |
| 4 | **검사기를 깨뜨려 봤는가** — 일부러 틀린 입력을 넣어 빨간불이 뜨는지 확인하고 **원복** | 통과만 확인하면 그 검사가 아무것도 안 잡아도 모른다 |
| 5 | **내가 틀렸던 것 / 스스로 잡은 것** | 숨기면 같은 실수가 다음 사람에게 간다. 자수는 감점이 아니다 |
| 6 | **막힌 것** — 숨기지 말고 즉시 | 늦게 알수록 비싸다 |

## 3. 검수 요청 전 — **"이제 안 고칩니다" 선언**

**이 문장을 보내기 전에는 검수를 시작하지 않는다.** 선언 뒤에는 지시 없이 아무것도 얹지 않는다.
검수 중 권고가 나오면 **모아뒀다가 한 번에** 반영하고, 재검은 **마지막 한 번**.

> 이걸 안 해서 2026-08-21 하루에 검수가 다섯 번 무효화됐다.
> **브랜치를 옮기거나 체크아웃을 바꿀 때도 알린다** — 남이 그 레포에서 무언가를 재고 있을 수 있다.

## 3-B. 확대·선택할 때 — **자리를 위치로 짐작하지 말고 식별자로 지정하라**

2026-08-21 하루에 **같은 유형이 두 번** 났다. 둘 다 "확인은 했는데 엉뚱한 것을 확인한" 경우다.

| 사고 | 무슨 일 | 결과 |
|---|---|---|
| 크롭 좌표 | 카드 하단을 확대한다고 좌표를 **눈대중으로** 잡았는데 테두리만 잡혔다 | *"숫자가 아니라 무늬"*로 **오판**. 다시 보니 진짜 숫자가 있었다 |
| 이미지 선택 | 내려받을 이미지를 **화면 순서(DOM)로** 골랐다 | 같은 카드를 **두 번** 받았다. 파일 크기가 같아서 겨우 드러났다 |

**규칙**
- **확대 검사에는 기준점을 함께 넣어라.** 크롭 안에 **알아볼 수 있는 표식**(카드 이름 글자·모서리·테두리 선)이 들어오는지 먼저 보고, 그게 맞아야 판정한다.
  → 이 방법을 도입한 직후 **심판 카드 크롭이 옆 카드로 밀려 있던 것을 즉시 잡았다.** 안 잡았으면 엉뚱한 카드를 비교한 자료가 형에게 갔다.
- **여러 개 중 하나를 고를 때는 순서·위치가 아니라 이름·id로 집어라.** 목록 순서는 언제든 바뀐다.
- **받은 것이 서로 다른지 확인하라** — 해시나 크기로. 같은 걸 두 번 받아도 겉으로는 정상으로 보인다.

> **왜 위험한가**: 이 실수는 **실패가 아니라 통과로 나타난다.** 검사를 돌렸고 결과도 나왔는데 대상이 틀린 것이라, 아무도 이상을 못 느낀다. [[A3]]의 "통과 오진"과 같은 뿌리다.

## 4. 검수할 때 — 검수관 5개

| # | 항목 | 왜 |
|---|---|---|
| 1 | **만든 사람 보고를 재현하라.** 숫자를 그대로 받아쓰지 마라 | 자기보고는 과다로도 **과소로도** 틀린다(31개라 했는데 실제 62개였던 적 있음) |
| 2 | **대조군을 둬라** | 전부 404면 "차단 성공"이 아니라 **서버가 죽은 것**일 수 있다 |
| 3 | **조회 실패를 부재로 읽지 마라** | 권한이 막혀 안 보이는 것과 없는 것은 다르다. 실제로 "예약 작업이 없다"는 오보가 났다 |
| 4 | **측정값이 이상하면 도구부터 의심하라** | 캐시·정션·다른 브랜치·배경 프로세스가 원인인 경우가 많다. 하루에 다섯 번 났다 |
| 5 | **치명·중대만 반려.** 경미는 통과 + 권고 | 완벽주의보다 속도. 동결 중이면 권고는 백로그로 |

## 5. 결재 요청할 때 — 정식 결재 카드(5이모지+송장ID) 필수 (2026-09-05 형 직접 지시)

형에게 결재를 요청할 때는 **일반 보고나 진행 대화에 섞지 말고, 반드시 정식 결재 카드 단독 메시지**로 올린다.
- **머리말**: `🟪🟪🟪🟪🟪 **결재 요청** 🟪🟪🟪🟪🟪`
- **송장 ID**: `송장 ID: REQ-YYYYMMDD-[이슈코드]-[순번]`
- **대상**: `형(@블랙하트) 승인이 있어야 진행합니다.`
- **내용**: `무엇을 / 왜 / 얼마나 / 위험 / 되돌리기` 코드블록 표
- **선택지**: `선택: 승인 · 보류 · 반려(취소)`
- **맺음말**: `🟪 승인하실 때까지 대기하고 있겠습니다. 🟪`

> **왜 있나 (2026-09-05 형 지시)**: 형이 이렇게 말했다 — *"기록하세요. 결재 요청 시 정식 결재 카드를 제출하세요!!!"* 결재 양식을 사용하지 않으면 수많은 대화 메시지 속에서 결재 요청을 찾을 수 없다.

## 붙임 — 실제로 났던 사고 목록 (지시서 3번 항목에 골라 쓸 것)

**코드·배포**
- 커밋했는데 push를 안 해 수 시간분이 로컬에만 있었다
- 실행 중인 화면을 커밋 상태로 착각했다 (양방향 오판 하루 2건)
- 브랜치 이동 뒤 빌드·타입검사 실패 → 원인은 코드가 아니라 `.next` 잔재. **빌드 먼저 → tsc 순서**로 해결
- `build | head` 처럼 파이프를 물려 빌드가 SIGPIPE로 중단됐다. **로그는 파일로 받고 grep**
- 같은 레포에 두 에이전트가 동시에 커밋해 커밋이 섞였다
- 안전망을 만들었는데 **한쪽 로케일만** 지키고 있었다(영어는 무방비)
- 구조상 절대 실패할 수 없는 항진식 테스트가 안전망 행세를 했다

**이미지·콘텐츠**
- 생성 이미지 결함 4종: **지어낸 글자 · 만자(卍) · 서명 · 얼굴**
- 부정 프롬프트("글자 쓰지 마")는 안 통한다. **소재에서 글자 쓸 표면 자체를 빼야** 한다
- 검사 구역 4개: **네 귀퉁이 · 상하단 · 중앙 확대 · 다른 산출물과 화풍 대조**. 중앙을 빼면 놓친다
- 개별 산출물 검사로는 **산출물 사이의 중복·불일치**를 못 잡는다. 격자로 늘어놓고 보는 층이 따로 필요하다
- 인계문서에 소재를 **요약**해 옮기다 빠뜨린 요소가 검사에서 통째로 사라졌다

**보고·소통**
- 파일 경로만 적고 첨부를 안 해 형이 파일을 못 받았다
- 운영 DB 비밀번호가 스크린샷으로 채널에 유출됐다
- 형에게 답을 안 보내고 혼자 일했다(19회 — 훅으로 해결)
- 추천안이 있는데 되물어서 형의 결정 횟수를 늘렸다
- 결재 요청을 일반 보고/대화에 섞거나 정식 결재 카드 없이 올려 형이 요청을 찾지 못함 (2026-09-05 형 직접 지시: "기록하세요. 결재 요청 시 정식 결재 카드를 제출하세요!!!")
- 업무 인계 시 멘션을 빠뜨려 다음 담당자가 작업을 이어받지 못하고 정체됨 (2026-09-05 형 직접 지시: "다음 담당자에게 업무를 넘길 때에는 멘션을 사용해야함. (규칙)")
