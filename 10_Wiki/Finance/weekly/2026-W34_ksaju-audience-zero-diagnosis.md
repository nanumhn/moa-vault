## 3. 왜 0인가 — 결정적 증거 3개

형이 물은 건 "왜 아무 효과가 없냐"다. 원인은 콘텐츠가 아니었다. **셋 다 배포 인프라의 문제**다.

### 증거 ① 인스타 자동게시는 **이틀 굴리다 꺼진 뒤 56일째 방치**돼 있다 [실측]

```
$ docker exec n8n n8n list:workflow --active=true
tarotDaily00001 | Daily Saju Tarot Card v3          ← 활성 (Discord 발송)
blogAutoPost001 | k-saju Blog Auto-Post             ← 활성
```
`tarotDaily00002 | Daily Saju Tarot Card v4 (IG Auto-Post)` — **존재하지만 비활성**(`workflow_entity.active = 0`).
IG 게시 노드 3개(`Get IG User ID` → `IG Create Media Container` → `IG Publish Post`)가 전부 만들어져 있는데 워크플로가 꺼져 있다.

**n8n 실행 통계 원본(`workflow_statistics`)으로 정확한 이력을 복원했다** — 시각은 UTC, 괄호가 KST:

| 이벤트 | 횟수 | 마지막 시각 |
|---|---|---|
| manual_success | 3 | 2026-06-20 18:03 (06-21 03:03) |
| manual_error | 4 | 2026-06-20 18:03 (06-21 03:03) |
| **production_success** | **1** | 2026-06-20 23:33 (**06-21 08:33**) |
| **production_error** | **4** | 2026-06-21 23:00 (**06-22 08:00**) |
| 이후 기록 | **없음** | 워크플로 비활성화: 2026-06-22 06:24 (15:24) |

> **[판정] 자동게시는 실제로 인스타에 한 번 성공했다.** 그러나 프로덕션 5회 중 4회가 실패했고(성공률 20%), **2026-06-22에 꺼진 뒤 오늘까지 56일간 아무도 다시 켜지 않았다.**
> 이건 "안 만들었다"가 아니라 **"만들어서 켰다가 깨졌는데 아무도 고치지 않았다"**다. 훨씬 나쁜 종류다 — 실패가 아무에게도 보고되지 않았다는 뜻이기 때문이다.

### 증거 ①-보정 — 토큰은 **지금 살아 있다** [실측, 2026-08-16 API 직접 확인]

> ⚠️ **이 항목은 내가 처음에 반대로 진단했던 것을 실측으로 뒤집은 것이다.** 기록으로 남긴다.

처음에 나는 `C:\Users\user\.moa\ig_token.txt`가 **39바이트**(Meta 토큰 형식 아님, 최종수정 06-21)인 것을 보고 *"유효한 토큰이 발급된 적이 없다 → 형이 재발급해야 한다"*고 진단했다. **틀렸다.**

실제 토큰은 그 파일이 아니라 **n8n 워크플로 노드 안에 인라인으로 들어 있었다.** 확인 결과:

```
GET https://graph.instagram.com/v21.0/me   →  HTTP 200
{"id":"36989077054041543","username":"ksaju.daily"}
```

- 토큰 길이 182자, `IGAA` 계열 = **정상 장기 토큰이며 2026-08-16 현재 유효**하다.
- ※ 검증은 값을 출력하지 않는 스크립트로 수행했고, 조회에 쓴 DB 사본은 즉시 삭제했다. 토큰 값은 이 문서·로그·대화 어디에도 남기지 않았다.
- **vault·git 유출 없음** [실측] — vault 사본 `n8n_daily_saju_card_v4_ig.json`에는 placeholder만 있고 실제 토큰 문자열이 없다(장문 리터럴 0개).

**⏰ 그래서 시한이 생겼다.** IG 장기 토큰은 60일이고 이 토큰은 2026-06-20경 발급됐다 → **2026-08-19 전후 만료 [추정]**. 그리고 **자동갱신 로직이 없다**(인수인계 문서가 "갱신 로직 필요"라고 남긴 그 항목이 미구현). 갱신 API는 **토큰이 살아 있는 동안에만** 호출된다.

> **결론이 뒤집힌다: 지금은 형이 아무것도 안 해도 된다.** cto가 오늘~내일 갱신 호출만 하면 60일이 연장되고 자동게시를 바로 켤 수 있다.
> **만료되고 나면** 인수인계 문서의 1~3단계(테스터 초대 → 수락 → 재발급)를 **형이 직접 해야 한다.** 즉 **3일 안에 손대면 형 작업 0분, 놓치면 형 작업 10분 + 재개 지연.**

### 증거 ② 매일 만든 카드가 **사내 디스코드로만** 갔다 [실측]

> **이것이 형이 "이렇게 일하고 아무런 효과가 없어"라고 느낀 구조의 정체다.**

## 7. CSO 자기점검 (숨기지 않는다)

1. **오너 없는 칸을 만들어 놓고 8주를 보냈다.** "IG(수동)"이라는 표기를 승인하면서 그 수동의 주체를 지정하지 않았다. 앞으로 **채널이 문서에 등장하면 그 자리에서 오너와 지표를 못박는다.**
2. **가동 여부를 확인하지 않고 "가동 중"이라는 문서를 믿었다.** 인수인계 문서는 "80% 완료"라고 정직하게 적어놨는데, 나는 이후 8주간 **한 번도 `list:workflow --active`를 쳐보지 않았다.** 앞으로 자동화 라인은 **문서가 아니라 실행상태로 확인**한다.
3. **data-finance 도달 불가가 2사이클 연속인데 에스컬레이션하지 않았다.** W33에 "복구되면 교체"라고 적고 방치했다. 측정자가 없으면 내 진단 전체의 신뢰도가 떨어진다 — **§8 결재 C로 올린다.**
4. **★이 문서를 쓰는 중에 내 진단 하나가 실측으로 뒤집혔다.** 나는 `ig_token.txt`가 39바이트인 것을 보고 *"토큰이 발급된 적 없다 → 형이 재발급해야 한다"*고 적었다. 실제로는 토큰이 다른 곳(워크플로 인라인)에 있었고 **지금도 유효**했다. 파일 하나를 보고 시스템 상태를 단정한 것이다.
   - 놓칠 뻔한 것: 그대로 보고했으면 **형에게 불필요한 작업 10분을 시키고, 48시간 시한(토큰 만료)을 놓쳐 실제로 그 작업이 필요해지게 만들 뻔했다.**
   - 잡은 방법: "내 진단이 틀렸다면 어디서 드러날까"를 역으로 찾았다(=v4가 과거에 실행된 적이 있는지 실행통계를 뒤졌다). **반례부터 찾는 절차가 실제로 오보를 막았다.**
   - 규칙화: **"~한 적이 없다"류의 부정 단정은 실행 이력·통계로 확인하기 전에는 쓰지 않는다.** 파일 존재/크기는 시스템 상태의 증거가 아니다.
