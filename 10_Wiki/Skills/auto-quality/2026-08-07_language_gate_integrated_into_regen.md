# 언어 게이트를 regen_artifact.py에 정식 편입 — 중국어 오염이 이틀 연속 재발했다

발견: 회의 `run_20260807_150625` (팀 `ppt_generation`) 품질 게이트
선행: [[2026-08-06_artifact_stage_has_no_language_gate]] — 어제 같은 사고, 근본 수리를 **백로그로 미뤘다가 다음 날 그대로 재발**했다.

## 무슨 일이

산출물 8종 중 **3종이 중국어 필러로 붕괴**했다.
- `content_density_playbook.md` — 2,986자 중 **960자(32.2%)** 가 중국어
- `ppt_tech_stack_comparison.md` — 1,780자 중 **404자(22.7%)**
- `use_case_priority.md` — 1,643자 중 **383자(23.3%)**

붕괴 지점의 문장이 결정적이다: `请继续输入中文内容。 [地平线 — 继续] 请继续完善和扩展提供的Markdown文档`
= "중국어 내용을 계속 입력하세요 / 제공된 Markdown 문서를 계속 보완·확장하세요".
**모델이 내 지시문("확장하라, 2,500자 이상")을 중국어로 자문자답하며 자기 자신에게 되돌려주고 있었다.**

부수로 `ppt_pipeline_decision.md`에 일본어 가타카나가 3건(`HTMLレンder`), `visual_asset_pipeline.md`에 한자 1건(`원稿`) 섞였다.

## 원인 (어제 진단과 같지만 방아쇠가 하나 더 있다)

1. **구조 원인(어제와 동일)** — `meeting.py`의 `speak()`에는 언어 게이트가 있는데 **산출물 단계와 `regen_artifact.py`에는 없다.** 발화는 걸러지고 vault에 영구 저장되는 산출물은 안 걸러진다.
2. **새로 확인한 방아쇠 — 분량 요구가 오염을 *유발*한다.**
   어제 노트는 "분량은 지시문에 숫자로 박아라(최소 2,500자)"를 룰로 남겼다. 그런데 **7B에 자기 능력 이상의 분량을 요구하면 할 말이 떨어진 지점부터 외국어 필러로 채운다.** 이번 오염 3건은 전부 "2,500자 이상" 확장 패스에서 발생했고, 1차 생성(800~1,200자)에서는 오염이 0건이었다.
   → **분량 요구와 언어 오염은 트레이드오프다.** 어제 룰(분량을 숫자로 박아라)을 그대로 따르면 오늘 사고가 난다. 분량을 올리려면 언어 게이트를 반드시 같이 걸어야 한다.

## 이번에 한 근본 수리 (백로그 해소)

`regen_artifact.py`에 언어 게이트를 정식 편입했다. 더 이상 임시 드라이버를 매번 짜지 않는다.
- `FOREIGN` / `FOREIGN_RUN` 정규식 `[぀-ヿ一-鿿]` 추가
- `LANGUAGE_LOCK` 문구를 **system·user 프롬프트 끝 양쪽에 반복 삽입** (어제 노트에서 효과 확인된 방법)
- 오염 감지 시 **최대 3회 재생성 루프**, 끝까지 실패하면 `strip_contamination()`으로 오염 구간을 잘라낸 것 중 **가장 긴 본을 채택**하는 폴백
- `strip_contamination()` — 외국문자 2자 이상 연속(`FOREIGN_RUN`)을 붕괴 지점으로 보고 그 이후를 버리며, 붕괴가 걸친 줄도 함께 버린다. `Hope this helps!` 트레일러도 같이 제거(어제 노트 3번 룰)
- 2자 이상 연속만 자르므로 `원稿` 같은 **단발 한자는 자르지 않고 재생성으로 유도** — 문서를 통째로 날리지 않기 위한 선택

## 룰 (다음부터)

1. **분량을 올릴 때는 언어 게이트를 반드시 함께 건다.** 둘은 세트다. 분량만 올리면 오염이 온다.
2. **분량 목표는 2,500자가 아니라 1,800~2,000자로 잡는다.** 이번에 2,500자를 요구한 것들이 붕괴했고, 목표를 낮춰 재생성하니 1,800~1,900자로 깨끗하게 나왔다.
3. **"1,500자 이상" 게이트만으로는 오염을 못 잡는다.** 오염본 3종은 전부 분량 게이트를 **통과**했다(2,986/1,780/1,643자). 오염이 오히려 글자 수를 늘려주기 때문이다. **분량 검사와 언어 검사는 독립적으로 둘 다 돌려야 한다.**
4. 검사는 항상 `PYTHONIOENCODING=utf-8`로 돌린다(cp949 콘솔이 먼저 터져 탐지 자체가 죽는다).

## 페르소나 조합 기록

`ppt_generation` = seojin(진행) + doyeon·serin·siwoo·seoa·narae·jio·jiwon (7명).

- **잘 작동**: serin(디자인 시스템 3,462자, 컬러 hex·타이포 pt·레이아웃 5종을 숫자로 확정) / siwoo(에셋 조달 2,919자, 조달처·fallback·용량까지) / narae(차트 JSON 스키마 + 출처 검사 항목을 QA 게이트에 넘길 형태로 제시 — **다른 패널 산출물과 물리는 유일한 발언**). 디자인·비주얼·데이터 축은 이 조합이 유효하다.
- **문제 — 진행자를 CTO로 세우면 결정문이 일정표가 된다.** seojin이 마무리에서 낸 것은 결정이 아니라 "누가 D-3까지 무엇" 식 담당자 배분이었고, **담당까지 틀렸다**(이서아=콘텐츠본부장에게 차트 삽입을, 박나래=분석가에게 자동 검사를 배정). 7B는 회의 후반부에 이름-역할 매핑을 잃는다. 기술 안건이어도 **결정문 품질이 중요하면 진행은 dohyun**, seojin은 패널로 두는 편이 낫다.
- **문제 — 브리핑에 사실을 박아도 모델이 뒤집는다.** briefing에 "Flux는 한글을 못 쓴다"를 명시했는데 강시우가 R2에서 "Flux로 한글 텍스트만 렌더하면 된다"고 **정반대로** 말했다. 이도연은 "저장률 12.3%"라는 **출처 없는 수치를 창작**했다(회사 금지 규칙). 브리핑 주입은 필요조건이지 충분조건이 아니다 → 정정 사실을 컨텍스트로 다시 주입해 재생성하니 최종본 8종 전부 정합해졌다.
- **facilitator 산출물은 여전히 엔진이 안 만든다.** `meeting.py`의 산출물 루프가 `panelists`만 돈다(구조상 그렇다). 진행자 결정문이 필요하면 매번 별도 호출로 보충해야 한다 — 이건 아직 백로그.

## 같이 고친 것

`vault_sync.py`의 `_slug()` — 40자로 자른 뒤 **끝에 공백이 남으면 Windows가 폴더를 못 만든다**(`mkdir` → WinError 3). 이번 회의 토픽이 정확히 그 경계에 걸려 vault 동기화가 통째로 실패했다("[vault sync] failed (non-fatal)"). 절단 **후에** 한 번 더 `rstrip(" .")` 하도록 수정.
→ 교훈: `.strip()[:n]`은 **자르기 전에 다듬는 것**이라 절단면을 못 지킨다. 순서가 반대여야 한다.
