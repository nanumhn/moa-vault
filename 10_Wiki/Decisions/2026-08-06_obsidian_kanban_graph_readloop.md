## 결정 (형 결재 필요)

### 1. 진실의 원천은 칸반이 아니라 프론트매터
카드를 사람이 손으로 옮기는 구조를 버린다. 각 노트의 YAML `status` 필드가 진실이고, 칸반·대시보드는 **dataview로 자동 집계된 표시**일 뿐이다.
`todo=할 일 / waiting=대기 중 / doing=진행 중 / done=완료 / hold=보류 / blocked=차단됨`

### 2. `02 Projects`에 모아 프로젝트 허브 노트 5개 신설
k-saju · 아투(american-todayz) · 덱스제나 · 쇼츠 자동발행 · 애드센스 블로그.
이것이 그래프 고립을 푸는 핵심 조치다. 허브가 생겨야 일지가 걸 링크가 생긴다.

### 3. 형 개인 칸반은 건드리지 않는다
`01 Dashboard/TODO.Kanban.md`는 형 개인 보드로 그대로 둔다. 모아 업무 보드는 **완전히 다른 파일명**으로 분리한다.
> ⚠️ 이도연 안의 `01 Dashboard/Todo.Kanban.md`는 대소문자만 다른 이름이라 윈도우에서 기존 파일과 충돌한다. **채택 불가 — 구현 시 다른 이름으로 교체할 것.**

### 4. 일지에 자동 백링크 — 단, 실재 확인 후에만
haru가 일지를 쓸 때 그날 건드린 프로젝트 허브 노트로 `[[링크]]`를 건다. 존재하지 않는 노트로의 링크는 만들지 않는다(깨진 링크 0개 유지).

### 5. 쓰기 전용 → 읽기-쓰기 루프
- **Pre-read**: 새 작업 시작 전, 관련 프로젝트 허브 노트와 매뉴얼을 먼저 조회하고 그 결과를 판단에 반영.
- **주간 회고**: 월요일 전략 리포트 시각에 지난 7일 일지에서 `막힌 것`·`클로 실수` 표기만 뽑아 회고에 반영.
- **반복 차단**: 같은 실수가 2회 이상 나오면 구조 수정 후보로 올린다.

### 6. 완료 판정에는 증거가 필요
카드를 `done`으로 옮기려면 커밋 해시 / 라이브 URL 재조회 값 / 파일 경로 중 하나 이상이 있어야 한다. 증거 없는 완료는 서지안이 반려.

### 7. 드리프트 감지
`doing` 상태로 7일 이상 변화 없음 → 경보. 최근 7일 일지 중 프로젝트 링크 0개 → 경보. 깨진 링크는 0개여야 한다. 경보는 `#drift-alert` 태그 + 디스코드.
