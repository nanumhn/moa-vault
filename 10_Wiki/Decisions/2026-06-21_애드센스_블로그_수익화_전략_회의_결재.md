## 3. 포스팅 자동화 방안 (n8n + 로컬 LLM + 스케줄)

**파이프라인:** 키워드 발굴 → AI 초안 생성 → **사람 1포인트 검수** → 자동 게시 → 알림

**n8n 노드 흐름 (포트 5678):**
1. **트리거** — Cron(예: 매일 오전 정해진 시각) 또는 수동 트리거
2. **키워드 소스** — 키워드 리스트(스프레드시트/구글시트 노드) 또는 SEO 키워드 큐
3. **LLM 생성** — HTTP Request → 로컬 LLM `localhost:1234/v1/chat/completions` (qwen2.5-7b). **구조화 템플릿 프롬프트**(제목/도입/H2 섹션/요약/FAQ)로 초안 생성. **API 비용 0**
4. **변환** — 마크다운 → HTML 변환(WordPress 블록 호환)
5. **검수 게이트** — 디스코드/슬랙으로 초안 푸시 → 사람 승인 시에만 게시(품질·팩트체크 1포인트)
6. **CMS 게시** — WordPress REST API(`/wp-json/wp/v2/posts`)로 자동 발행(draft → publish)
7. **알림** — 게시 완료 시 디스코드 알림

**게시 플랫폼:** **WordPress 1순위**
- 근거: 애드센스 친화적(승인 사례 풍부), 플러그인 SEO(Yoast/RankMath), REST API로 n8n 자동게시 즉시 연동. Next.js 자체 구축은 자유도는 높으나 SEO·애드센스 통합·운영 부담이 1인에게 과함 → **WordPress로 빠르게 띄우고, 검증 후 Next.js 이전은 차후 검토**.

**스케줄·처리량:**
- 발행 빈도: **주 5~7편**(초기 축적기엔 더 집중 가능). 이론상 LLM 처리량은 주 20편까지 가능하나, **사람 검수 병목**과 품질을 고려해 **주 5~7편이 현실치**.
- 사람 검수 개입: 게시 직전 1포인트(팩트·중복·어색한 문장 교정).

**로컬 LLM(qwen2.5-7b) 품질 한계 보완책:**
- **구조화 템플릿 강제**(섹션 고정 프롬프트)로 산만함 방지
- **자체 해설·예시 추가**로 단순 정보 나열 → 차별화(중복콘텐츠 회피)
- 팩트가 중요한 수치/스펙은 **사람 검수에서 1차 확인**
- 한 번에 1편씩 생성(맥락 길이 부담↓), 7B 노이즈(오타·외국어 혼입)는 검수 단계서 컷
