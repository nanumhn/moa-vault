## 1. 제품 정의 (확정)
형의 초안 가설이 **그대로 성립**한다고 판단.

> 여러 명(멀티테넌트 — 한 시스템을 여러 고객이 각자 격리된 채 나눠 쓰는 구조)이 각자 네이버 블로그를 등록하면,
> 매일 정해진 시간에 글을 대신 써서 자동으로 올려주는 **구독형 SaaS**(월정액 소프트웨어 서비스).

- 1순위 타깃: 자영업자 · 병원/학원 원장 · 부동산 중개사 · 1인 마케터 · 블로그 대행사
- 고통: 블로그는 해야 하는데 매일 글 쓸 시간이 없다
- 대체재: 직접 쓰기(무료·시간 소모) / 사람이 하는 블로그 대행(월 30~50만원대)

## 2. 최대 의사결정 — 포스팅 실행 방식은 "보류 후 분기"

**이번 회의에서 A/B를 확정하지 않는다.** 단 하나의 미확인 사실에 결론이 종속되기 때문.

| 항목 | 안 A: 에이전트(브라우저 자동화 봇) | 안 B: 노드서버(공식 API) |
|---|---|---|
| 원리 | 사용자마다 봇이 실제 네이버에 로그인해 글쓰기 버튼을 누름 | 서버가 공식 통로로 직접 포스팅 |
| 안정성 | **낮음** | **높음** |
| 차단·계정정지 위험 | **높음** (자동화 탐지·캡차) | 낮음/없음 |
| 비용 | 계정 수만큼 브라우저 필요 → 선형 증가 | 낮음 |
| 성립 조건 | 항상 가능 | **네이버가 글쓰기 API를 열어줘야만 성립** |

### ★분기 계획
- 공식 글쓰기 API 발급 **가능** → **안 B 채택**
- 발급 **불가** → 안 A 채택 (차단 위험을 안고 감)
- 둘 다 부적합 → **제3안**: 초안만 만들어 주고 발행은 사용자가 누르거나, 사용자 PC에서 도는 프로그램

### [미확인] 확인이 필요한 단 하나의 질문
> **"네이버 블로그 글쓰기 공식 API가 현재 신규 발급 가능한가?"**

- 현재 네이버 개발자센터가 공개 제공하는 블로그 API는 **검색(읽기 전용)**으로 알려져 있음
- 과거의 글쓰기 API(`openapi.naver.com/blog/writePost`)는 수년 전 종료된 것으로 알려져 있으나 **이번에 재확인하지 못했다**
- 이 회의는 외부 조회 수단 없이 진행됐다. **단정하지 않는다.**
- 확인 담당: cto-seojin (네이버 개발자센터 직접 조회 + 필요시 네이버 문의)

## 3. 사용자 플로우 (7단계)
가입 → 블로그 연결 → 구글시트 연동 → 콘텐츠 주제 등록 → 예약 설정 → 자동 발행 → 결과 확인

- **구글시트 용도 확정**: 사용자가 글감 목록을 직접 채워 넣는 창구 + 발행 결과 로그를 되돌려 받는 창구(양방향)
- 발행 실패 시: 실패 사유를 명시해 알리고, 수동 발행·재시도 선택지를 준다

## 4. 아키텍처 개요
| 구성요소 | 하는 일 | 기술 |
|---|---|---|
| 관리툴(웹 대시보드) | 사용자 정보 등록·상태 확인 | Next.js |
| 사용자 정보 저장소(DB) | 설정값 저장 | PostgreSQL |
| 구글시트 연동 | 글감 수급·결과 로그 | Google Sheets API |
| 스케줄러(정해진 시각 자동 실행 장치) | 예약 발행 트리거 | cron + Node.js |
| 글 생성기 | 콘텐츠 생성 | 로컬 LLM(LM Studio) |
| 포스팅 실행기 | 실제 발행 | 안 A면 Puppeteer+Chrome / 안 B면 API 호출 |

## 5. ★보안 원칙 (회의 최대 수확)
**사용자의 네이버 아이디·비밀번호를 우리 서버에 보관하지 않는다.** — 범위 밖(절대 안 만듦)으로 확정.
대안 2개: ① 사용자가 직접 세션을 연결 ② 사용자 본인 PC에서 도는 프로그램.
이 원칙이 안 A의 매력을 크게 떨어뜨리므로, 안 B 또는 제3안 쪽으로 무게가 기운다.

## 6. MVP(최소기능제품 — 가장 작은 첫 버전)
- **IN**: 멀티테넌트 등록·관리 / 구글시트 연동 / 예약 자동 발행 / 실패 사유가 보이는 결과 확인 페이지
- **OUT(v2)**: 검색 노출 보장, 다중 플랫폼
- **범위 밖(절대 안 함)**: 사용자 계정 비밀번호 서버 보관

## 7. 가격 (초안 — 재검토 필요)
회의 제안은 단일 프리미엄 **월 48만원**, 무료 체험 1주.
→ COO 의견: **단일 고가 플랜은 위험**. 근거 수치가 회의 중 흔들렸다(대행 시세를 50~100만원/60만원으로 각각 다르게 인용). 형 결재 항목으로 남긴다.

## 9. 형(CEO) 결재 필요 항목
1. **제품 방향 승인** — 위 정의대로 갈지
2. **가격 플랜 결정** — 48만원 단일 플랜 vs 다층 플랜
3. **페이즈 0 착수 승인** — 네이버 공식 API 확인을 cto-seojin에게 넘길지

## 10. Kill 기준 (접어야 하는 조건)
- 공식 API 불가 + 브라우저 자동화도 차단이 잦아 발행 성공률이 실용 수준에 못 미칠 때
- 발행은 되는데 네이버 저품질 판정으로 검색에 안 잡혀 고객 가치가 0일 때

## 미결·주의
- 가격·서버비용·원가 수치는 **7B 모델 추정치이며 근거 미검증**. 재계산 필요.
- 네이버 저품질(기계 생성 글의 검색 노출 제한) 리스크는 이 사업의 존폐 변수인데, 회의 대응이 "일 1회 제한" 수준에 머물렀다. 별도 심화 필요.
