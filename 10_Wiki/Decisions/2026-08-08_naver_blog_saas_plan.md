## 1. 제품 정의 (확정)
형의 초안 가설이 **그대로 성립**한다고 판단.

> 여러 명(멀티테넌트 — 한 시스템을 여러 고객이 각자 격리된 채 나눠 쓰는 구조)이 각자 네이버 블로그를 등록하면,
> 매일 정해진 시간에 글을 대신 써서 자동으로 올려주는 **구독형 SaaS**(월정액 소프트웨어 서비스).

- 1순위 타깃: 자영업자 · 병원/학원 원장 · 부동산 중개사 · 1인 마케터 · 블로그 대행사
- 고통: 블로그는 해야 하는데 매일 글 쓸 시간이 없다
- 대체재: 직접 쓰기(무료·시간 소모) / 사람이 하는 블로그 대행(월 30~50만원대)

## 2. 최대 의사결정 — 포스팅 실행 방식은 "보류 후 분기"

**이번 회의에서 A/B를 확정하지 않는다.** 단 하나의 미확인 사실에 결론이 종속되기 때문.

| 항목 | 안 A: 에이전트(브라우저 자동화 봇) | 안 B: 노드서버(공식 API) |
|---|---|---|
| 원리 | 사용자마다 봇이 실제 네이버에 로그인해 글쓰기 버튼을 누름 | 서버가 공식 통로로 직접 포스팅 |
| 안정성 | **낮음** | **높음** |
| 차단·계정정지 위험 | **높음** (자동화 탐지·캡차) | 낮음/없음 |
| 비용 | 계정 수만큼 브라우저 필요 → 선형 증가 | 낮음 |
| 성립 조건 | 항상 가능 | **네이버가 글쓰기 API를 열어줘야만 성립** |

### ★분기 계획 → **2026-08-08 분기 확정됨**
- ~~공식 글쓰기 API 발급 **가능** → **안 B 채택**~~ → **불가 확정 (아래 확인 결과)**. **안 B 폐기**
- 발급 **불가** → 안 A 채택 (차단 위험을 안고 감) → 단, 5장 보안 원칙(비번 서버 저장 금지)과 충돌해 **안 A도 원안 그대로는 불가**
- **→ 현재 유효한 선택지는 제3안**: 초안만 만들어 주고 발행은 사용자가 누르거나, 사용자 PC에서 도는 프로그램
- **→ 추가 선택지(신규 발견)**: 타깃을 **네이버 카페**로 바꾸면 공식 쓰기 API가 살아있어 안 B가 그대로 성립

### [확인 완료 — 2026-08-08, cto-seojin] 결론: **공식 글쓰기 API 없음 → 안 B 불성립**

> **질문: "네이버 블로그 글쓰기 공식 API가 현재 신규 발급 가능한가?"**
> **답: 아니오. 발급 이전에 엔드포인트 자체가 존재하지 않는다.** (라이브 서버 직접 검증)

#### 근거 1 — 레거시 엔드포인트가 게이트웨이에서 제거됨 (가장 강한 증거)
`POST https://openapi.naver.com/blog/writePost` 직접 호출 결과:
```
HTTP/1.1 404 Not Found
{"errorMessage":"/blog/writePost : API does not exist.","errorCode": "051"}
```
`GET /blog/listCategory`도 동일(051). 네이버 서버가 스스로 "존재하지 않는 API"라고 응답한다.

#### 근거 2 — 대조군 실험으로 "051 = 삭제됨"임을 확정 (인증 실패와 구분)
같은 조건(무인증)으로 호출했을 때 **살아있는 API는 전부 401 인증오류**를, **없는 API는 404/051**을 반환한다.

| 엔드포인트 | 응답 | 해석 |
|---|---|---|
| `GET /v1/search/blog` (블로그 검색) | 401 · `024` 인증실패 | **살아있음** |
| `POST /v1/cafe/{clubid}/menu/{menuid}/articles` (카페 글쓰기) | 401 · `028` OAuth헤더 없음 | **살아있음** |
| `POST /calendar/createSchedule.json` (캘린더 등록) | 401 · `028` | **살아있음** |
| `GET /v1/nid/me` | 401 · `024` | **살아있음** |
| `POST /blog/zzzznonsense` (내가 만든 가짜 경로) | 404 · `051` | 없음 |
| **`POST /blog/writePost`** | **404 · `051`** | **없음 — 가짜 경로와 완전히 동일** |

→ 블로그 글쓰기는 "권한이 없어서 막힌 것"이 아니라 **경로 자체가 라우팅되지 않는다.** 신청·제휴로 열 수 있는 상태가 아니다.

#### 근거 3 — 현행 공식 문서에서 블로그 글쓰기가 삭제됨
- 공식 API 목록(`/docs/common/openapiguide/apilist.md`)의 **로그인 방식(쓰기 가능) API = 네이버 로그인 · 카페 · 캘린더**뿐. 블로그 없음.
- 로그인 API 명세 목차(`ko/login/SUMMARY.md`) = 로그인 / 회원프로필 / **카페** / **캘린더** / 네이버페이 배송지. **블로그 명세 없음.**
- 목록에서 블로그가 등장하는 곳은 **① 검색 API `/v1/search/blog`(GET, 읽기 전용) ② 네이버 공유하기** 둘뿐.

#### ★함정 — "아직 있다"는 오정보의 출처 (중요)
네이버 공식 저장소에 `naver-openapi-swagger.json`이 남아 있고, 거기엔 `/blog/writePost`가 **파라미터까지 상세히**(title, contents, image, categoryNo, options.openType…) 적혀 있다.
그러나 **이 파일의 마지막 커밋은 2017-09-20**이고 저장소 자체는 2026-08-07까지 갱신 중이다. 즉 **9년 방치된 잔존 파일**이다.
→ 웹 검색이나 AI 답변이 "네이버 블로그 글쓰기 API 있다"고 하면 십중팔구 이 파일을 근거로 삼은 것이다. **문서가 아니라 라이브 응답을 믿을 것.**

#### 대안 통로 조사 결과 (전부 부적합)
| 통로 | 실체 | 자동 발행 가능? |
|---|---|---|
| 네이버 공유하기 | `share.naver.com/web/shareView`로 **브라우저를 이동**시켜 사용자가 직접 확인·게시. URL+제목만 전달 | **불가** (사용자 클릭 필수, 본문 작성 아님) |
| 스마트에디터 튜토리얼 | 스마트에디터 3.0이 인식하는 **HTML 서식 규격 문서**일 뿐. 발행 통로가 아님 | **불가** (단, 발행 통로가 생기면 본문 서식 규격으로 재활용 가치 있음) |
| 유료/제휴 API | 유료 API는 **캡차·기계번역 2종뿐**. 문서의 제휴신청 링크(`/openapi/cooperation`)는 현재 **404** | **불가** |
| RSS | 네이버 블로그 RSS는 **내보내기(읽기) 전용**. 공식 카탈로그 전체에 외부→네이버 인바운드 발행 통로 없음 | **불가** |

#### ★부수 발견 (사업적으로 중요) — 카페는 공식 글쓰기 API가 살아있다
`POST /v1/cafe/{clubid}/menu/{menuid}/articles`가 **정상 동작 중**(401 인증오류 = 존재). 네이버는 **카페·캘린더에는 쓰기 API를 열어두고 블로그만 닫았다.**
→ 동일한 SaaS 구조를 **네이버 카페 자동 포스팅**으로 돌리면 안 B(공식 API)가 그대로 성립한다. 별도 검토 가치 있음.

#### [불명확] 확정하지 못한 부분
- **종료 공지 원문·정확한 종료일**: 개발자센터 공지사항이 클라이언트 렌더링이고 데이터 API가 403이라 원문 미확보. "수년 전 종료"는 정황(2017년 이후 문서 방치)과 일치하나 **공식 공지로는 확인 못 함**. 단, 종료 여부 자체는 라이브 404로 확정됐으므로 사업 판단에는 영향 없음.
- **비공개 엔터프라이즈 제휴로 블로그 발행권을 받을 수 있는지**: 공개 근거가 존재도 부재도 확인 불가. 공개 제휴 링크는 죽었고 문의 이메일(`dl_naver_openapi@navercorp.com`)만 남아 있음. 필요하면 형 명의로 문의 가능하나, 게이트웨이에서 경로가 삭제된 점을 볼 때 기대치는 낮다.

## 3. 사용자 플로우 (7단계) — ★2026-08-08 형 보완지시 반영(승인 완료)
가입 → 블로그 연결(최대 3개) → PC 에이전트 설치·페어링 → 구글시트 연동 → 예약 설정 → 자동 발행(제약 적용) → 결과 확인

- **블로그 연결 상한**: 사용자당 **최대 3개**. 요금제 연동 — **기본 1개 포함, 추가 블로그는 상위플랜**(형 승인, 가격 세부안은 페이즈1에서 확정)
- **구글시트 용도**: 사용자가 글감 목록을 직접 채워 넣는 창구(기본, 무료 포함) + **AI 글감 대행 채움(유료 업셀 옵션)** + 발행 결과 로그를 되돌려 받는 창구(양방향). → 미정이던 가격 구조(48만원 단일 vs 다층)를 "기본 저가 시작 + 글감대행 업셀"로 자연스럽게 풂
- **발행 빈도 제약**: 블로그 1개당 **하루 최대 2회, 최소 12시간 간격**. 목적: 네이버 저품질(기계생성 검색배제) 리스크 완화 — 8장 미결 항목의 구체적 대응책
- **PC 에이전트 상태 감시**: 서버-에이전트가 **주기적으로 통신(하트비트/상태체크)**. 대시보드에 "에이전트 오프라인이라 오늘 발행 못 함" 실시간 표시 가능 — PC꺼짐으로 인한 무통보 발행실패 방지
- **이벤트 로그**: 최종 성공/실패값만이 아니라 액션별 **단계 타임스탬프**(요청됨→실행중→완료/실패) 기록
- 발행 실패 시: 실패 사유를 명시해 알리고, 수동 발행·재시도 선택지를 준다

## 5. ★보안 원칙 (회의 최대 수확)
**사용자의 네이버 아이디·비밀번호를 우리 서버에 보관하지 않는다.** — 범위 밖(절대 안 만듦)으로 확정.
대안 2개: ① 사용자가 직접 세션을 연결 ② 사용자 본인 PC에서 도는 프로그램.
이 원칙이 안 A의 매력을 크게 떨어뜨리므로, 안 B 또는 제3안 쪽으로 무게가 기운다.

## 6. MVP(최소기능제품 — 가장 작은 첫 버전)
- **IN**: 멀티테넌트 등록·관리 / 구글시트 연동 / 예약 자동 발행 / 실패 사유가 보이는 결과 확인 페이지
- **OUT(v2)**: 검색 노출 보장, 다중 플랫폼
- **범위 밖(절대 안 함)**: 사용자 계정 비밀번호 서버 보관
