# 💡 픽셀 오피스 시각화 설계

자율 회사 OS의 ⑦ 비주얼 레이어 — agent-town 스타일 픽셀 오피스 — 의 **기준 설계 문서**. 형이 2026-05-31에 직접 작성해서 던져준 기획안 + 라이선스 분석을 정리.

## 핵심 철학

AI 에이전트(직원)의 활동 상태를 픽셀 아트로 시각화 → 대시보드의 직관성 ↑, 게임 같은 재미 ↑. 단순 "조직도"가 아닌 "**살아 움직이는 인공지능 가상 오피스**".

---

## 1. 에이전트 상태별 픽셀 시각화 — 3 레이어 분리

| 상태 | 캐릭터 애니메이션 | 오브젝트 상호작용 | 머리 위 말풍선/Emote |
|---|---|---|---|
| **Idle (대기)** | 제자리 idle bob | 의자 착석, 모니터 대기 | `...` 또는 `zZz` |
| **Thinking (LLM 호출)** | 머리 감싸기/까딱 | 모니터 빠르게 깜빡임 | 🧠 또는 💡 (반짝이는 전구) |
| **Working (작업)** | 격렬한 타이핑 | 책상 스탠드 점등 | 프로그레스 바 / ☑️ |
| **Success (완료)** | 만세 / 가벼운 점프 | 모니터 녹색으로 | ✅ 녹색 체크 |
| **Error (예외)** | 고개 떨굼 / 당황 | PC 연기 / 붉은 불 | ⚠️ 빨간 느낌표 / 💀 |

핵심: 3개 레이어를 **Phaser Container**로 묶고 자식 노드로 두면 자연스러운 분리 + 동시 갱신.

## 4. 개발 구현 프로세스

### Step 1: 상태 메타데이터 규격화 (Backend / Agent)

상태를 Enum으로 정의하고 **WebSocket 또는 SSE로 push** (현재 폴링 → 즉각 반응으로 업그레이드).

```json
{
  "agent_id": "siwoo",
  "agent_name": "강시우",
  "status": "THINKING",
  "target_object_id": "desk_4"
}
```

### Step 2: 픽셀 스프라이트 시트 분할 + 매핑 (Frontend)

- 16x16 그리드 표준 (LimeZu 또는 Maru 기준)
- 에이전트 ID마다 SpriteRenderer / Phaser Container 할당
- 캐릭터 + 오브젝트 + 말풍선을 자식 노드로

### Step 3: 렌더링 상태 업데이트 로직

상태 이벤트 수신 → 애니메이션 파라미터 변경 + 말풍선 prefab `Instantiate` (또는 활성/비활성).

## 5. 🛡️ 보안 체크포인트 (웹 기반 서비스)

웹 브라우저에서 픽셀 에셋의 원본이 노출되면 → 라이선스 위반(무단 배포 방조) 소지.

**대응:**
1. **스프라이트 시트 노출 방지**: F12 개발자도구로 png 통째 다운로드 못 하게.
2. **번들러로 난독화**: Webpack/Vite (Next.js 16의 turbopack도 동일 가능).
3. **스프라이트 아틀라스 분할**: 큰 시트를 잘게 쪼개 번들링.
4. **Canvas 내부 렌더링**: Phaser는 기본 Canvas 사용 — 직접 원본 접근 어렵게.
