# nblog-saas PC 에이전트 샌드박스 크래시 대장정 (2026-08-11)

## 무슨 일이 있었나

형이 nblog-saas PC 에이전트(네이버 블로그 자동발행용 설치형 앱) 설치파일을 처음 공개배포(옵션A: 자체서버 직접서빙)한 직후, 실기 테스트 중 "창이 떴다가 바로 사라짐" 크래시를 발견. 하루 종일 진단→수정→재검증을 반복하며 v0.1.0 → v0.1.4까지 총 5개 버전을 순차 배포.

## 원인 규명 과정 (오진 포함, 정직하게 기록)

1. **1차 진단(오진)**: Windows Error Reporting 이벤트로그에서 예외코드 `0x80000003`(STATUS_BREAKPOINT) + "GPU process isn't usable. Goodbye." FATAL 로그를 보고 "GPU 드라이버 문제"로 판단 → v0.1.1(`app.disableHardwareAcceleration()` 상시적용)로 수정했으나 재발.
2. **2차 진단(정답)**: agent.log 실측 결과 `gpu=off`인데도 GPU 프로세스뿐 아니라 **렌더러 프로세스까지 동일 exitCode로 크래시** — 즉 GPU 자체가 아니라 **크로미움 샌드박스 초기화가 그 PC에서 실패**하는 게 진짜 원인. `--no-sandbox`로 실행하면 정상 작동 확인.
3. v0.1.2: 시작 60초 내 자식프로세스 2회 크래시 감지 → `--no-sandbox --disable-gpu`로 자동 재시작 + 그 결정을 `compat-mode.json`에 영구 기록(재부팅해도 유지, 사용자는 평생 크래시 한 번만 목격).
4. v0.1.3: 발행용 네이버 크롬(별도 Playwright 프로세스)에도 같은 지뢰가 있었음 발견 — 동일 안전모드 로직 적용.
5. v0.1.4: 발행 버튼이 네이버 에디터의 "도움말" 팝업에 가려 클릭 실패(Playwright `locator.click: Timeout 15000ms exceeded`, "subtree intercepts pointer events"). 특정 팝업 셀렉터를 콕 집지 않고 **"가려졌는가"를 감지해서 범용으로 걷어내는 방어 로직**으로 수정(형이 "팝업이 산발적으로 뜨고 이벤트배너도 뜬다"고 알려준 게 결정적 — 1회성 dismiss로 짰으면 다음 배너에 또 죽었을 것).

## 부가 발견

- **`checkLogin()`의 `page.close()` 무조건호출 버그**: 사용자가 "네이버 로그인 확인" 버튼을 눌렀을 때 로그인 안 된 상태면 로그인폼 탭이 뜨자마자(1~2초) 자동으로 닫혀버림 — 사용자 입장에선 "로그인창이 열렸다 닫힌다"로 보임. 사용자 직접호출과 백그라운드 폴링을 구분해서, 직접호출일 때만 탭을 유지하도록 수정.
- **설치폴더 ACL 이론**: 형의 다른 AI워커("덱스"/Codex)가 "설치폴더에 BUILTIN\Users 등 샌드박스용 실행권한이 빠져서 죽는다"는 이론을 제시하고 자기 PC에 커스텀 로컬그룹(`CodexSandboxUsers`)을 만들어 RX 권한을 부여해 해결했다고 주장. cto-seojin이 자기 개발PC로 반증(그 3개 SID가 원래 없어도 정상 작동) → 근본원인으로 단정은 못 했으나, 원리 자체는 실재하고 비용 0이라 예방차원으로 설치스크립트에 반영(SID 기반, 이름 기반은 한국어 윈도우에서 조용히 실패하는 함정 확인).
- **빌드 신뢰성 함정**: 0.1.4 첫 빌드가 NSIS `Can't open output file`로 조용히 실패해 140KB짜리 깨진 설치파일이 남았는데, 백그라운드 작업 알림은 "완료(exit 0)"로 표시됨. 파일 크기를 직접 확인하지 않았으면 깨진 설치파일을 그대로 배포할 뻔함.

## 교훈

- **증상을 원인으로 단정하지 말 것.** GPU 크래시는 샌드박스 실패의 증상이었지 원인이 아니었다. 재현 가능한 환경(다른 PC, 다른 사용자)에서 반례를 찾는 게 제일 빠른 검증이었다.
- **"성공(exit 0)" 알림을 곧이곧대로 믿지 말고 산출물을 직접 검증할 것** — 파일 크기, 해시, 실제 동작까지.
- **사용자가 준 힌트(형: "팝업이 산발적으로 뜬다")가 좁은 수정과 범용 수정의 갈림길이었다.** 사용자 관찰을 코드보다 먼저 반영해야 할 때가 있다.
- **여러 독립 진단 소스(우리 cto-seojin + 형의 다른 AI워커)가 각자 다른 각도로 같은 문제를 파다 보니 교차검증이 자연스럽게 일어났다** — 한쪽이 놓친 걸 다른 쪽이 잡았다(page.close 버그는 덱스가, GPU 오진 정정은 cto가).

## 결과

v0.1.4가 정식 배포로 승격(`AGENT_RELEASE_*` 갱신+push 완료). 실제 발행은 1차 시도 실패(팝업 방해, 수정 전 버전으로 시도했기 때문) 후 재시도 대기 중(만료 16:35 KST). v0.1.5가 checkLogin 버그 수정+ACL 예방조치+버튼 다크모드 버그 수정을 담아 빌드 중.
