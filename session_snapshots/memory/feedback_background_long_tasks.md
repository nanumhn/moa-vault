★상시 운영 규칙(형 명시 2026-06-26): **"너와 대화는 항상 유지되어야 하고, 작업 시간이 필요한 건 에이전트를 백그라운드로 진행하자."** 형과의 디스코드 대화는 항상 살아있어야 한다(절대 안 막힘). 이미지/영상 생성, 대용량 다운로드, 긴 빌드처럼 오래 걸리는 서브에이전트·명령은 **반드시 백그라운드(run_in_background)** 로 돌린다. foreground로 잡으면 그 시간 동안 형 디스코드 메시지에 답을 못 해 형이 "질문에 대답이 없어"라며 답답해한다. 2026-06-26 시우 이미지 재생성을 foreground로 돌려 형 질문 3개를 놓침 → 형이 직접 "이미지 생성하면 다른 일 못하냐? ComfyUI 제어 서브에이전트로 분리해라"고 정확히 지적, 이어 상시 규칙으로 못박음.

**Why:** 형은 0순위로 빠른 디스코드 회신을 원한다([[feedback_acknowledge_first]], [[feedback_reporting_cadence]]). 컴퓨터/GPU가 막히는 게 아니라 **클로의 응답 턴이 막히는** 게 문제다. 백그라운드로 던지면 작업은 뒤에서 돌고 나는 계속 대화·다른 일 가능, 완료 알림(task-notification)이 오면 그때 결과를 전달하면 된다.

**How to apply:**
- media-head-siwoo(이미지·영상)·대용량 다운로드·긴 빌드 = `run_in_background: true`로 Agent/Bash 호출.
- 던진 직후 형에게 "백그라운드로 돌리는 중, 끝나면 가져올게요" 한 줄 + 그 사이 형의 다른 질문/작업에 계속 응답.
- 완료 알림 받으면 결과(이미지 파일 등)를 디스코드로 전달.
- 짧은 작업(몇 초)은 foreground 무방. '형이 기다리는 동안 내가 묶이는가'가 기준.
