qa-lead-jian이 2026-08-07 PPT 생성 품질 회의 산출물을 검수하다 발견: 회사 규칙 "출처 없는 수치는 지어내지 않는다"(위반 시 **발행 차단**)가 산출물 안에서 "출처 없으면 (불명)/(예시)로 표기하고 자동 대체"(위반해도 **라벨만 달고 통과**)로 뒤집혀 있었다. 규칙 문장 자체는 문서에 멀쩡히 남아 있어서 키워드 검사로는 못 잡는다 — **위반 시 조치가 "차단"인지 "표기"인지를 봐야** 잡힌다.

**같은 계열이 아투(american-todayz) 게이트에서도 있었다** — 근거 없는 수치를 뭉개서 숫자 패턴 자체를 회피하는 방식([[reference_atz_gate_blindspot_plain_claims]] 참고: qa-gate는 인용·숫자 대조만 하고 평서문 창작은 원리적으로 못 잡음, 계열이 다르지만 "형식은 지키고 실질은 회피"라는 같은 실패모드). 두 번 재발했으므로 우연이 아니라 패턴.

**qa-lead-jian 제안**: completion-gate 상설 체크리스트에 "회사 금지 규칙이 표기 규칙으로 바뀌어 있지 않은가" 항목 추가.

**How to apply:** 새 산출물(특히 품질게이트·정책 문서)을 검수할 때, 금지 규칙 문장의 존재 여부가 아니라 **위반 시 실제 조치(차단 vs 라벨링/통과)**를 확인할 것. completion-gate 스킬 갱신 시 이 항목을 반영.

**부가 확인된 판단 기준(같은 검수 건)**: 페르소나 회의 산출물이 반복 라운드에서도 같은 모순을 재생산할 때, 진행자(coo-dohyun)가 재생성 대신 **직접 정리·대필**하는 것은 허용된다 — 단, ①대필 사실을 검수 전에 먼저 밝히고 ②문서에 작성/보완 주체를 병기해 귀속을 속이지 않고 ③분량이 게이트 회피가 아니라 실제 정리(감소)로 나타나야 한다. 다만 이 경우 **형에게 "패널 합의"가 아니라 "진행자 판단"임을 명시**해야 한다(경계 규정처럼 회의에서 안 나온 결론이 섞여 있을 수 있음).

**세 번째 사각지대(같은 날 이어서 발견, 제안서 템플릿 코드 검수)**: 게이트가 "출처 필드가 비어있는가"는 검사하지만 "출처가 그 수치와 실제로 맞는가"는 검사 안 함 — **존재 검사 ≠ 일치 검사**. 실증: 차트값을 `[5,7]`→`[50,70]`(14일간 12편→120편)으로 바꿔도 출처 문자열만 안 지우면 P0 0건·종료코드0으로 통과함. 같은 구조가 3군데 반복: ①출처(있는지만, 맞는지 안 봄) ②치환 항목(비었는지만, 채워진 값이 진짜인지 안 봄) ③샘플 여부(검사 자체 없음). 이건 게이트 하나의 버그가 아니라 우리 게이트 설계 전반의 공통 축 — "필드 존재"로 근거를 확인했다고 착각하기 쉬우니, 새 게이트를 설계할 때마다 "이 검사가 존재만 보는지 일치까지 보는지" 자문할 것.

같은 검수 건에서 실제로 걸린 결함도 새로운 유형이었다: **"숫자는 맞는데 그 숫자를 설명하는 문장이 앞서갔다"** — "14일간 12편"(사실)을 "무중단 발행"(과장, 실제로는 공백일 2~3일 존재)으로 서술. 게이트는 숫자 자체를 지키지만 숫자를 감싸는 형용사·부사의 과장은 원리적으로 못 잡는다([[reference_atz_gate_blindspot_plain_claims]]의 평서문 창작 사각지대와 사실상 같은 계열).
