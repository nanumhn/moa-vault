**보고를 실제보다 나쁘게 쓰는 것도 거짓이다.** 우리는 낙관적 포장을 경계하는 습관이 있어서
비관 방향은 "정직한 것"으로 착각하기 쉬운데, **검증 안 된 비관은 검증 안 된 낙관과 똑같은 사실 오류**다.

## Why

2026-08-17 주간 전략 리포트(W34)에서 서지안 검수가 같은 유형을 반복해서 잡았다.
**중대 반려 5건 중 3건**(소개 페이지·가드·감시 장치)이 이 유형이었고, 권고 1건까지 합쳐 4곳. 전부 한 방향이었다.

| 내가 쓴 것 | 사실 |
|---|---|
| "아투에 소개 페이지가 없다" | `p/about.html` 200 실존, 홈에서 3회 링크. **연락처·정정요청 경로까지 이미 있었음** |
| "AI 고지가 0건" | 본문 텍스트 고지만 없고 **이미지 AI 고지문은 이미 있었음** |
| "MoaMcpGuard가 죽어 세션 2시간18분 사망" | **가드는 정상 작동**(감지→재시동 2회→자력 복구). 죽은 건 MCP 연결이고 세션은 살아 있었음 |
| "안 돌았다를 보는 장치가 없어 아무도 몰랐다" | 자동 감시 작업 **19개가 등록돼 정상 가동 중**. 정확히는 세 곳에만 안 붙어 있었음 |

**대가:** QA 라운드가 한 번 더 돌았고, 형에게 나간 리포트에 정정을 3차까지 이어 보내야 했다.
그리고 **형이 실제보다 나쁜 그림으로 의사결정할 뻔했다** — 특히 "소개 페이지 없음"은
형이 할 일을 *"페이지 신설"* 로 만들어 없는 작업을 시킬 뻔했다(실제로는 *"한 줄 추가"*).

★그런데 **정확한 사실이 오히려 더 강한 주장이었다.** "가드가 죽었다"(틀림)보다
**"가드는 잘 돌았는데 알림 임계값이 3회라 형에게 2시간38분간 아무 통보가 없었다"**(맞음)가
문제를 훨씬 날카롭게 짚는다. 과장은 논지를 세게 만드는 게 아니라 **반증 가능하게 만들어 약화시킨다.**

## How to apply

1. **부정적 서술에도 [확인] 근거를 요구한다.** "없다 / 죽었다 / 아무도 몰랐다"는 긍정 주장만큼
   엄격하게 검증한다. 없음의 증명은 **도구가 그것을 볼 수 있는지**부터다([[feedback_verify_measurement_before_declaring_failure]]).
2. **"전부 / 유일한 / 하나도 없다 / 아무도"** 를 쓰기 전에 반례를 한 번 찾는다([[feedback_find_counterexample_first]]).
   이번 4건 중 3건이 이 단어들에서 터졌다.
3. **정정할 땐 같은 사실이 언급된 모든 위치를 grep으로 훑는다.** 진단부만 고치고
   결재부·결론부를 놓치면 **한 문서가 같은 사건에 대해 반대되는 말을 하고**, 하필
   형이 읽고 결정하는 곳은 후자다. (서지안 지적, 실제로 발생)
4. 자기비판이 필요할 땐 **극적으로 쓰지 말고 정밀하게 쓴다.** 정밀한 쪽이 늘 더 세다.
