## 원래 있던 것 / 없던 것

브리지에 **TUI 모드가 이미 있었다**(`tmux.mjs`, `TUI_PANE`, `TUI_CHANNEL_ID`, `scripts/tui-up.sh`). 그런데
- **맥/tmux 전용**이고 이 PC엔 tmux가 없다 → **한 번도 켜진 적 없음**. 설정칸도 비어 있었다.
- 출력을 codex **롤아웃 JSONL 파일**에서 tail하는 구조라 **codex 전용**이었다(agy는 그 파일이 없음).
★형 지적: *"제나·덱스를 설치한 지가 언젠데 이제 와서 그 기능이 안 켜져 있다고 얘기하면 어떻게 하니"* — 8/6 윈도우 이식 때 이 부분만 빠졌고 **아무도 확인 안 했다.** "설치됨"과 "작동함"을 같은 걸로 취급한 것.

| 파일 | 역할 |
|---|---|
| `C:\Users\user\.moa\moa_console.ps1` | 창에 글자 넣기·화면 읽기. `AttachConsole(pid)` + `WriteConsoleInputW`(CONIN$) / `ReadConsoleOutputCharacterW`(CONOUT$). 포커스 불필요 |
| `C:\Users\user\.moa\moa_cli_window.ps1` | 덱스·제나 CLI를 창으로 기동/상태/종료. PID를 `cli_windows.json`에 기록. 멱등 |

**맥판보다 나아진 점**: 답을 롤아웃 파일이 아니라 **화면에서** 읽으므로 **제나(agy)도 된다**.

## ★실측으로 잡은 함정 6개 (전부 같은 날)

1. **본문과 Enter를 한 번에 보내면 TUI가 제출하지 않는다.** 본문 넣고 잠시 뒤 Enter만 따로. (맥 tmux 구현에도 같은 주석이 있었다 — 원인이 같다)
2. **PS 5.1은 `0x80000000`을 Int32로 읽어** uint32 캐스트가 깨진다 → 10진수 리터럴로.
3. **권한이 다르면 창에 못 붙는다.** 클로 셸이 **관리자(High)** 라 거기서 띄운 창도 High가 되는데, 브리지는 작업 스케줄러가 **Limited(Medium)** 로 돌린다 → `AttachConsole err=5`. **창도 Medium으로 띄워야 한다.**
4. **작업 스케줄러로 띄우면 콘솔이 아예 없다** → `err=87`. 권한은 맞는데 창이 없다. → `explorer.exe` 경유(Explorer가 Medium이라 자식도 Medium + 진짜 콘솔).
5. **"새로 생긴 줄"로 답을 고르면 안 된다.** 터미널이 스크롤하면 옛 줄이 화면에 다시 들어와 전부 '새 줄'로 잡힌다(제나 첫 응답에 몇 분 전 덱스 에러가 통째로 딸려 나옴). → **"방금 넣은 질문 아래"** 를 기준으로.
6. **공유 채널의 문맥 큐가 남의 대화를 창에 주입한다.** 형 지적: *"여기는 덱스 창이 아니야.. 제나인데???"* — 제나 창이 덱스 대화로 도배됐다. CLI 모드에선 문맥 큐를 끈다(창은 그 직원의 작업 공간이다).

## ★★승인 프롬프트 구멍 — 실제로 터지기 전에 막았다

`pasteToPane` 은 본문을 넣고 **무조건 Enter를 따로** 보낸다. 그래서 창에
`Do you want to proceed? > 1. Yes` 가 떠 있는 동안 **디스코드 메시지가 하나 들어오면
그 Enter가 1번(Yes)을 눌러 사람 확인 없이 명령이 실행된다.**
서진이 코드에서 먼저 찾았고, 형 확인 결과 그날 승인은 형이 직접 누른 것이어서 **아직 안 터졌다.**

곁가지로 같은 뿌리의 문제 하나 더: 승인 대기로 끝난 턴은 화면이 잠잠해서 `waitForReply`가
'답 완료'로 판정하고 **프롬프트 글자를 그대로 형에게 답으로 내보냈다**(실측, 형이 받음).

**막은 방식**: 넣기 전 화면을 읽어 승인/선택 화면이면 넣지 않고 예외 → 디스코드로 ⚠️.
판정 문구는 **실제로 본 것만** 사용. codex 명령 승인 문구는 아직 관측 못 해 '알려진 구멍'으로 주석.

1. **백슬래시 유실** (`D:\Develop\...` → `D:Developjena-workspace`)

   **브리지에 닿기 전에 사라졌다.** 실사용 경로(디스코드→브리지→제나)는 왕복 무손실 확인.
