**증상**: 윈도우 터미널 탭에서 **한글이 안 쳐진다.** 한/영 키를 누르면 `@` 가 찍히고, 한글 자판이 영문 그대로 들어간다(`dfsddsfdfdf`). 오른쪽 Alt·`Win+Space` 도 안 먹는다.

**원인**: 그 **윈도우 터미널 프로세스**가 오래 떠 있으면서 입력기(IME)가 물린 것. 2026-08-23 실측 — 새벽 04:28에 자동 기동으로 뜬 WT가 18시간 뒤 이 상태였다.

**해결**: **그 터미널 창을 완전히 종료하고 새로 띄운다.** 그러면 바로 풀린다. 설정을 고칠 필요 없다.

## ★오진하기 쉬운 지점 (실제로 다 의심했다)

- **"CLI 프로그램이 한글 입력을 못 받는다"** — agy가 Go 바이너리라 그럴듯했다. 아니었다.
- **"창 여는 방식이 잘못됐다"** — 형이 직접 연 맨 PowerShell 탭에서도 재현되니 아니다. **이게 결정적 대조군이었다.**
- **"키보드 종류 설정이 안 맞다"** — `PCAT_101AKEY / Subtype 3`(한/영=오른쪽 Alt)로 잡혀 있어 의심했지만, 메모장에서는 멀쩡히 됐으므로 시스템 설정 문제가 아니었다.
- **"권한 때문이다"** — 관리자 WT에서는 되고 일반 WT에서는 안 돼서 그럴듯했다. 실제로는 **그냥 그 프로세스가 물린 것**이고, 관리자 창은 우연히 멀쩡했던 것.

**가르는 방법**: 같은 터미널에서 **CLI가 아닌 맨 셸 탭**에 한글을 쳐 본다.
- 거기서도 안 되면 → 그 **터미널 프로세스** 문제(껐다 켠다)
- 거기선 되는데 특정 앱만 안 되면 → 그 앱의 한계

## 곁가지로 확인된 사실

- 로그온 기동 작업 중 **`클로드 코드 디스코드 연결` 만 RunLevel=Highest**(관리자)로 등록돼 있다. 나머지(MoaDexBridge·MoaJenaBridge·MoaBootNotify·MoaSessionReset)는 전부 Limited.
  형은 관리자로 실행한 적이 없다 — 작업 등록이 그렇게 돼 있던 것. **언제 왜 그렇게 넣었는지는 기록이 없다.**
  이 권한 차이가 [[project_dex_jena_cli_window_bridge_2026-08-23]] 의 attach 거부(err=5)와 "같은 명령인데 실행자에 따라 갈림"의 원인이었다.
