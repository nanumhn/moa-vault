[[feedback_check_tool_can_false_pass]] 가 **도구를 의심하라**(검사자 쪽)면, 이건
**보고를 어떻게 적느냐**(보고자 쪽)다. 2026-08-21 타로 작업에서 이것 때문에
사고 두 건이 실제로 막혔다.

- "중앙부는 축소본으로만 봤다" 를 적었더니 클로가 중앙부 검사를 지시했고,
  거기서 **여사제 두루마리의 지어낸 한자**가 나왔다. 안 적었으면 그대로 나갔다.
- 검사표에 **교체 대상만** 적고 승인 4장을 빼놓았더니, 클로가 그 누락을 보고
  승인분을 따로 확인했다.

**Why:** "22장 전부 통과" 라고 쓰면 **검사하지 않은 영역까지 그 숫자 안에 들어간다.**
읽는 사람은 전수로 읽는다. 같은 날 이 실패를 네 번 했다(색조 도구 / 귀퉁이 /
중앙부 / 홈 이미지 20.9MB).

**How to apply:**
- 검사 보고는 **"본 것" 과 "안 본 것" 을 나눠** 적는다. 한계를 적는 것이 신뢰를 깎지
  않는다 — 오히려 상급자가 판단할 수 있게 만든다.
- **전칭(전부·하나도·전혀)은 전수로 확인한 것에만** 쓴다.
- 검사표에는 **교체 대상이 아니라 검사 대상 전체**를 넣는다.
- 숫자를 옮기기 전에 **그 숫자가 무엇을 세는지** 확인한다. 홈 이미지가 20.9MB 로
  4배 부풀려졌던 건 304 응답의 `encodedBodySize` 를 합산했기 때문이다.
  측정과 계산 두 경로가 같은 값을 낼 때 믿는다.
