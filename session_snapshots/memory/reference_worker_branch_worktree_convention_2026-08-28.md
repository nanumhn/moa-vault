2026-08-28 형이 "서브에이전트 병렬처리 기본 + 각자 본인 브랜치"를 제안했고, 덱스가 아래 구조로 확정해 "앞으로 기본 운영으로 적용"한다고 형께 보고했다.

```
역할
덱스           기준 커밋 고정 · 업무 분해 · 통합 브랜치 · 최종검수
클로           clo/<이슈>-<업무> 브랜치와 전용 worktree
제나           jena/<이슈>-<업무> 브랜치와 전용 worktree
서브에이전트   읽기 분석은 병렬, 수정 필요하면 별도 브랜치

안전 규칙
1. 시작 전 모두 같은 base SHA 확인
2. 같은 파일을 두 담당자에게 동시에 안 맡김
3. 각자 자기 브랜치만 수정·시험·커밋
4. 결과는 해당 이슈방에 해시·파일·시험과 함께 직접 보고
5. 통합은 덱스가 전용 integration 브랜치에서만 수행
6. 병합·배포·재시작은 형 승인 후 실행
7. 읽기·시험만 하는 담당자는 불필요한 브랜치를 만들지 않음
```

**How to apply:** 앞으로 덱스가 클로에게 작업을 배정할 때 `clo/<이슈>-<업무>` 브랜치명을 지정하면 그 규칙을 따른다. 병합은 클로가 하지 않고 덱스의 integration 브랜치가 흡수하거나, 덱스가 명시적으로 병합을 위임할 때만 한다(오늘까지의 패턴은 덱스가 커밋만 위임하고 병합은 클로가 대신 실행해왔는데, 이 새 구조에서는 5번 규칙상 통합이 원칙적으로 덱스 담당으로 바뀐 것으로 보인다 — 다음에 실제로 적용되는지 확인할 것).
