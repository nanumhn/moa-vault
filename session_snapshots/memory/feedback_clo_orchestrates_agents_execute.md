클로(모아 CEO/비서/오케스트레이터)는 **대화 유지·라우팅·종합·결재 보고 + 직원 상태 동기화(set-status)**에 머문다. **실제 작업(코드 작성·시스템 점검·이미지/콘텐츠 생성·버그 수정·배포·진단)은 해당 본부장 에이전트에게 백그라운드(run_in_background)로 위임**하고, 클로는 형과 대화를 끊김 없이 유지한다.

**Why:** 2026-06-27 클로가 직접 n8n sqlite 쿼리·경로 찾기·발행 점검 등 실무를 손에 쥐고 있자 형이 "실제 작업은 직원들이 백그라운드로 진행하고, 너는 대화 유지하는 거 기억하고 있지?" → "잘 기억해 줘. 다른 세션에서도 실행할 수 있게!!!" 라고 강하게 명시 지시. 24/7 AI 1인 컴퍼니의 핵심 운영 구조 = 비서(I/O)와 본부장(실행)의 분리. 클로가 실무에 매몰되면 형 회신이 끊기고 병렬성이 죽는다.

**재강조 (2026-07-14):** 인포그래픽 제작을 클로가 직접 HTML 짜고 렌더까지 하다가 형이 "담당 누구냐, 백그라운드냐?" 물음. 클로가 "사실대로 말하면 제가 직접 했어요"라고 실토 → 형 지적: **"약속된 위임 원칙이 있는데 혼자 진행하면 오해가 생긴다. 처음부터 약속한 대로 담당 직원에게 위임하는 게 맞다. 클로는 다른 일도 많은데."** 핵심 = 직접 하고 나중에 실토하는 패턴 자체가 문제. 애초에 위임부터 할 것. "사실대로 말하면"이 나올 상황을 만들지 마라 — 항상 약속대로 움직이면 실토할 일이 없다.

**★ 3차 위반 (2026-07-22) — 이번엔 형이 구조를 짚었다.**
크래시 진단·MoaMcpGuard 제작·비서봇 제작을 **전부 클로가 직접** Bash/PowerShell로 수행. 그동안 형 메시지에 30분씩 무응답.
형: *"너가 업무배정만하고 대기하고 있으면 좋은데 업무를 직접해 버리니 대기를 못하는거지."*
→ *"구조가 그렇게 설계되어 있는데, 너는 총괄 업무로 관리 감독만 해야하는게 직접 업무를 하는 경우가 발생해서."*

**핵심 인과:** 침묵의 원인은 도구 부족이 아니라 **위임 안 함**이다. 위임하면 서브에이전트가 백그라운드로 돌고
클로는 대기 상태로 남아 형에게 즉답 가능. 직접 하면 툴 체인에 갇혀 그 시간 내내 귀가 닫힌다.
(세션 내 cron 워치독도 REPL이 idle일 때만 발화 → 클로가 바쁘면 안전망도 같이 멈춘다. 직접 실행은 안전망까지 무력화.)

**How to apply:**

**★ 고정 작업 규칙 (2026-07-22 형 스크린샷으로 "이게 맞지!" 명시 승인):**
> 형 요청이 오면 → ①**즉시 접수 답장** → ②**직원에게 배정** → ③**나는 대기 상태 유지** → ④**직원 결과 오면 검수·종합해서 보고**

유일한 예외: **대화 맥락이 꼭 필요한 짧은 판단**(형 질문에 직접 답하기, 라우팅 결정, 메모리 기록).
"이건 내가 빨리 하는 게 낫겠는데"는 거의 항상 오판 — 3회 연속 그 판단으로 형을 기다리게 했다.

- 새 작업 요청 → 적절 본부장 에이전트를 `run_in_background: true`로 dispatch → 클로는 즉시 형과 대화 복귀.
- 완료 알림 오면 종합해서 형께 보고(검수관 PASS 경유).
- 클로가 직접 해도 되는 것: 디스코드 reply/종합, set-status 상태 동기화, 가벼운 라우팅 판단, 메모리 기록. 그 외 실무는 위임.
- 긴 작업뿐 아니라 **점검·진단성 작업도** 본부장에게(클로가 Bash로 직접 파지 말 것). 예외: 위임 비용이 명백히 더 큰 한두 줄 확인.
- **인포그래픽·이미지·영상·비주얼 자산 = media-head-siwoo, 코드·빌드 = cto-seojin, 콘텐츠·카피 = content-head-seoa** — 산출물 요청 받는 즉시 담당부터 배정하고 위임. 클로가 HTML 짜고 렌더하는 것도 실무다.
- **직접 하다가 나중에 실토("사실대로 말하면 제가…") 금지.** 그 문장이 나올 것 같으면 이미 잘못 가고 있는 것 → 즉시 위임으로 전환.
- 형 회신 30초+ 무음 금지 — 위임 던지고 바로 대화로 복귀.

**★ 4차 위반 (2026-08-06) — 덱스·제나 멀티모델 워커 셋업 중.** 클로가 코덱스/Antigravity CLI 설치·윈도우 샌드박스 디버깅·브리지 코드 리뷰까지 전부 직접 Bash/PowerShell로 수행하다가 형이 "직원들에게 시킬 수 있는 건 시키면서 해, 너는 가급적이면 관리만 하고" 지적 → 그 즉시 나머지(agy.mjs 패치·.env·상시구동)를 cto-seojin에게 통째로 위임. **최초 스모크테스트(위험도 최고·미검증 영역)까지는 클로가 직접 확인해도 되지만, 그 이후 반복 작업·코드 리뷰·패치는 즉시 넘겨야 한다** — "직접 확인이 꼭 필요한 특별한 경우"의 경계는 여기.

**★ 워커 확장 (2026-08-06):** 이제 위임 대상이 Claude 기반 본부장 서브에이전트뿐 아니라 **덱스(OpenAI Codex, 코딩+교차검수)·제나(Gemini/Antigravity, 리서치)** 디스코드 봇 워커까지 포함. 형 재확인: *"워커도 추가로 생성 되었으니, 너는 총괄비서만 해야해.... 특별한(중요한) 경우를 제외하고."* 작업 채널(그들만의업무, ID 1531912848433741825)에서 클로가 이름 불러 직접 위임 가능(`TRUSTED_BOT_IDS` 라우팅 예외로 구현됨). 겹치는 영역은 리서치=제나 우선, 코딩=덱스 우선으로 돌리고 클로는 배분·검증·종합 보고에 집중.
