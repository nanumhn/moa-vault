2026-08-12 밤 SMTP 배포 작업 중(cto-seojin) 발견. 운영서버 `.env.production`의 에이전트 공식 포인터가 여전히 **0.1.9**로 남아있다(작업 전 백업본도 동일). 하지만 [[project_open_threads_2026-08-13_dawn_snapshot.md]] 등 메모리엔 "에이전트 0.1.12 승격 완료"로 기록돼 있다.

현장 배포 흔적을 보면 0.1.1/0.1.8/0.1.11은 있는데 0.1.12는 직접 다운로드 URL 1건만 있고, 공식 포인터 갱신이 파일에 안 남아있다 — 승격 작업이 어딘가에서 누락된 것으로 보인다(에이전트가 잘못 보고했을 가능성 또는 갱신 자체가 실행 안 됐을 가능성).

cto-seojin은 임의로 값을 바꾸지 않고 그대로 두었다.

**Why**: 공식 포인터가 stale하면 사용자 PC의 "최신버전" 판정이나 자동업데이트 안내가 실제와 어긋날 수 있다.

**How to apply**: 형에게 "0.1.12를 공식으로 올려도 되는지" 확인 요청 보냄(2026-08-12 23:30경) — 답변 오면 `.env.production`에 반영하고 이 메모리 종료 처리할 것. 승인 전까지는 0.1.9가 공식값이라는 전제로 취급.

**2026-08-13 08:38 KST 최종 완료**(형 승인 후 cto-seojin 반영): `.env.production`의 `AGENT_RELEASE_VERSION/URL/SHA256` 갱신 + pm2 재시작 + `pm2 save`까지 완료, 재부팅해도 안 되돌아감. `/release/latest` 실측으로 0.1.9·0.1.11→"업데이트있음", 0.1.12→"최신" 판정 확인. exe는 재빌드 안 하고 기존 0.1.12 빌드(sha256 대조 확인)를 그대로 연결. 곁다리로 업데이트 비교 로직이 문자열이 아니라 마디별 정수 비교라 "0.1.9 < 0.1.12"가 정확히 성립하는 것도 확인함(문자열 비교였으면 뒤집혔을 자리). 현장 PC들이 실제로 갈아타는지는 각 PC에서 업데이트 알림을 눌러야 확정 — 별도 확인 필요하면 그때 체크. 이 이슈는 종료.
