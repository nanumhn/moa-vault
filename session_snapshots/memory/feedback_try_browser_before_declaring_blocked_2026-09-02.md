형 지시(2026-09-02, IG 토큰 재발급 작업 중): *"브라우저 실행도 하지 않고, 안된다고 하고. 너무 그러지 마"*

**경위**: n8n 운영 워크플로 수정을 위해 웹 UI가 필요했는데, `127.0.0.1:5678`로 접속했더니 로그인 화면이 나와서 "로그인이 필요해서 못 한다"고 형께 바로 보고했다. 형이 "브라우저를 띄워봐"라고 재지시하자 다시 시도했더니 `localhost:5678`(다른 호스트명!)로는 이미 로그인된 세션이 있었다 — 쿠키가 호스트명에 스코프돼 있어서 `127.0.0.1`과 `localhost`가 다른 세션으로 취급된 것이었다.

**Why**: 형은 "안 된다"는 결론을 내리기 전에 실제로 다른 진입 경로(다른 호스트명, 다른 프로필, 새로고침 등)를 시도해봤는지를 중요하게 본다. 첫 시도 실패로 바로 "로그인 필요 → 저는 못 함"으로 단정한 게 문제였다.

**How to apply**: 브라우저/CLI로 뭔가 확인·수정해야 할 때, 첫 접속 시도가 로그인 화면이나 권한 에러를 보이더라도 즉시 "안 된다"고 보고하지 말 것. 최소한 다음을 시도한 뒤에 결론 낼 것:
- 같은 서비스의 다른 호스트명(localhost vs 127.0.0.1 vs 실제 도메인)
- 이미 열려있는 다른 브라우저 프로필/탭에 세션이 남아있는지
- 새 탭으로 재시도

정말 로그인(비밀번호 입력)이 필요한 지점에 도달하면 그건 여전히 형이 직접 해야 한다(시스템 프롬프트 금지사항) — 하지만 "로그인 화면이 뜬다"와 "로그인이 필요하다"는 다른 판정이므로 성급히 합치지 말 것.
