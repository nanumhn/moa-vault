"커밋 완료"라는 보고를 받아도 **push(GitHub 등 원격저장소 반영)까지 확인하기 전엔 백업됐다고 보고하지 않는다.** 특히 새로 만든 레포는 `git remote`가 아예 안 걸려있을 수 있다.

**Why:** 2026-08-08 네이버블로그SaaS(`nblog-saas`) 개발 중 cto-seojin·덱스가 매 라운드 "커밋 완료"라고 정확하게 보고했는데, 정작 레포 자체에 GitHub 원격저장소 연결이 안 돼 있어서 수 시간 분량의 작업이 이 PC에만 있는 상태였다. 형이 "github에는 푸쉬 되고 있니?"라고 직접 물어서 발견됨. 이어서 "커밋 저장한다는 거 표시하는 건 그러면 어디다 한다는 거야? 잘못된 정보야?"라고 재확인 — 보고 자체는 거짓이 아니었지만 커밋≠푸시 구분을 형에게 명확히 안 알린 게 문제였음.

**How to apply:** 새 레포를 시작할 때는 **가장 먼저** `git remote add`(또는 `gh repo create`)로 원격 연결부터 만들어두고, "기본적으로 레포 만들고 세팅을 시작해야지"라는 형 지적대로 이건 매번 허락받을 일이 아니라 **프로젝트 착수 시 당연히 먼저 해야 하는 기본 세팅**으로 취급한다. 진행상황 보고 시 "커밋 완료"와 "push 완료(원격 반영)"를 구분해서 쓰고, 특히 여러 에이전트(cto-seojin·덱스 등)가 순차로 작업하는 프로젝트는 라운드마다 `git status`/`git log origin/main..HEAD`로 미푸시 커밋이 쌓여있지 않은지 주기적으로 점검할 것.
