덱스·제나·클로가 같이 쓰는 이슈처리 포럼 스레드(예: [브리지 이슈 003])에서는 메시지를 보낼 때 **의도한 수신자를 반드시 멘션(`<@id>`)으로 표시**한다.

**Why:** 형이 직접 지시(2026-08-29 00:28, chat_id 1542901265346990204) — "메시지 남길 때 대상을 맨션으로 걸어 주세요. 그러지 않으면 확인이 안 돼요." 형은 화면에서 멘션 유무로 그 메시지가 누구를 향한 것인지 판단한다. 멘션이 없으면 형이 "이게 나한테 하는 말인가, 덱스한테 하는 말인가"를 못 가른다.

**How to apply:**
- 형께 보고/질문이면 `<@348731432086274049>`(형)를 붙인다.
- 덱스·제나에게 하는 말이면 해당 워커 ID를 붙인다(덱스=1531914747069599855, 제나=1531914807341486184).
- 여러 명에게 동시에 해당하면 다 붙인다.
- 이 규칙은 [[reference_calling_convention_nickname_vs_mention_2026-08-27]](부르는 법: 형은 별칭, 워커끼리는 멘션)의 연장선 — 거기서는 "부르는 법"이었고, 이번엔 "메시지 끝/시작에 대상 멘션을 실제로 붙이라"는 더 구체적인 지시.
- Shared_Rules 머리말/맺음줄 태그와 별개로, 멘션은 그 태그 안이 아니라 본문에 붙인다(실제 사례: 본문 첫 줄이나 끝줄에 `<@id>`).

**★2026-08-29 00:28 덱스가 한 단계 더 강화**(형 지시 직후, 같은 스레드): "이후 이 스레드의 지시·검수 요청·결과 보고에는 반드시 실제 수신 대상을 멘션해주세요. **대상 없는 상태 보고와 상호 확인 메시지는 보내지 않습니다.**"
→ 이건 클로가 그동안 [브리지 이슈 003] 스레드에서 남발하던 "(확인만 남깁니다: ...)" 류의, 특정 수신자 없이 그냥 눈도장 찍는 방관자성 메시지를 **더 이상 보내지 말라는 뜻**이다. 앞으로는:
  - 정말 대상(형/덱스/제나 중 하나 이상)이 있고 그 대상이 실제로 필요로 하는 내용일 때만 멘션과 함께 보낸다.
  - 그냥 "봤다/대기한다"는 무대상 확인 메시지는 하지 않는다 — [[feedback_dont_ack_every_dex_status]]와 같은 방향.
  - 다만 이건 훅 차단("가장 최근 Discord 메시지에 실제 reply 없음")과 충돌할 수 있다 — 그 경우 하네스 요구가 우선한다는 걸 이미 여러 번 확인했으니, 멘션이라도 붙여서 최소한으로 보내되 내용 없는 반복은 줄인다.
