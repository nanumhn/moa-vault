2026-07-30, 아투 기사 작성을 qwen → ChatGPT 로 넘기며 하루 종일 밟은 것들.
**실패 8건 중 7건이 GPT 문제가 아니라 내 배선/판단 문제였다.** 형이 "실패가 너무 빈번하고 토큰도 많이 쓴다"고 지적.

## ★가장 큰 교훈 — 검사를 붙일수록 그 검사가 새 실패를 만들었다

형 지적: **"앞 뒤 맥락없이 프롬프트를 날리고 있어"**, **"너가 gpt 사용을 잘 못하고 있는것 같은데"**

- 자동 이어쓰기(잘림 감지 → "이어서 계속" 자동 발송)가 **완결된 한 줄 답변**을 잘렸다고 오판해 헛소리를 보냈고, GPT가 "이어 쓸 앞부분이 대화에 없다"고 답했다. 기사용 판정(출처 줄 유무)을 아무 답변에나 들이댄 것.
- → **애매하면 자동으로 재촉하지 말고 그대로 돌려주고 사람이 판단하게 한다.**

## 밟은 함정 (전부 실측)

| 증상 | 진짜 원인 |
|---|---|
| 컴포저에 입력 안 됨 | `.focus()` 만으론 안 잡힌다. contenteditable 이라 **실제 포인터 이벤트** 필요 |
| 2글자를 완성 응답으로 회수 | 전송 직후엔 정지버튼이 아직 없고 빈 답변칸만 있어 "스트리밍 아님+길이 안정"이 성립. → **스트리밍 1회 이상 관측 + 최소 길이** 조건 추가 |
| 로그인 안 됨으로 오판 | SPA 재렌더 순간 컴포저가 사라진다. 한 번 보고 단정 금지, 재확인 4회 |
| 주문 글자가 하나씩 사라짐 | **나눠 넣기(insertText 반복)가 글자를 흘린다.** 90자→40자로 줄여도 샜다. → **한 번에 통째로** 넣으면 2,821자 정확히 일치 |
| 소제목이 전부 사라짐 | 화면 글자(innerText)만 긁으면 `### ` 가 렌더링되며 소실. → **DOM 구조를 보고 `<h3>` → `###` 복원** |
| CDP timeout: Runtime.evaluate | 내 CDP 호출 타임아웃(180초)이 페이지 안 폴링(420초)보다 짧았다. **안쪽이 도는데 바깥에서 끊은 것** |
| 회차가 갈수록 답이 짧아짐 | 주문이 **같은 대화에 계속 쌓였다**(5턴). 앞 기사와 재촉이 문맥에 남아 GPT가 혼란. → 기사 1편 = 새 대화 1개 |
| 웹 검색을 함 | 주문에 "검색하지 마"가 없었다(**지침에만** 있었다). GPT는 눈앞의 주문을 더 크게 본다 |

## 주문서 쓰는 법 (형 교정)

자료만 던지고 한 줄 시키면 안 된다. **앞에 목적 → 가운데 자료 → 뒤에 요구사항.**
```
아투 블로그에 올릴 한국어 시사 기사 한 편을 써줘.
[이번 건] 제목후보·매체·보도일·링크(확인용)
[원문] …
[이렇게 써줘]
· 위 [원문]에 있는 사실만. ★웹 검색하지 마. 링크도 열지 마
· 분량 900~1,300자
· ★중간에 멈추지 말고 끝까지 쓴 다음 출처 줄로 마무리
```

## ★★ 진짜 원인 — 화면에서 읽고 있었다 (2026-07-30 형이 확정)

**오늘 "실패"라고 형에게 보고한 것들은 대부분 실패가 아니었다. GPT는 다 썼고 내가 못 읽었다.**

```
GPT가 쓴 것    1,475자 (소제목 5개 · 한국절 · 출처줄까지 완결)
내가 읽은 것    293자  → "문장 중간에 잘렸다"고 보고
```

`innerText` 로 화면에 그려진 글자를 긁었는데, **창이 최소화돼 있으면 브라우저가 아래쪽을 아예 그리지 않는다.**
그래서 창 상태와 성패가 정확히 갈렸다(앞 4전 4승 / 최소화 전패). 나는 이걸 보고 "백그라운드라 응답이 끊긴다"고
진단했지만, 끊긴 것은 **응답이 아니라 렌더링**이었다. 형이 그 대화의 전문을 직접 붙여주셔서 확정됐다.

**해결**: 화면이 아니라 **대화 데이터**에서 읽는다 — `/backend-api/conversation/<id>`.
★대기(완료 판정)도 같이 옮겨야 한다. 읽기만 바꿨더니 "다 썼나" 판정이 화면을 보고 있어서 `2자`로 타임아웃했다(반쪽 수정).
★빈 자리표시 메시지(assistant 0자)를 거르고 골라야 한다 — `create_time` 이 null 이라 정렬이 흔들려 빈 것이 마지막으로 잡힌다.

### 여기서 나온 규칙 (형 지시로 코드에 넣음)

**"안 나왔다"고 말하기 전에, 다른 경로로 한 번 더 본다.**
화면으로 읽었으면 데이터로, 데이터로 읽었으면 화면으로 대조하고 차이가 나면 로그에 남긴다.
오늘은 그 역할을 형이 대신 해주셨다 — 캡처 6장과 전문 붙여넣기로.

### 내가 연달아 틀린 진단들 (전부 한 번 보고 단정한 것)

| 내 진단 | 실제 |
|---|---|
| "프로젝트 메모리가 오염됐다, 대화를 지워야 한다" | 틀림. 형이 막아서 멀쩡한 대화 10개를 안 지웠다 |
| "백그라운드라 GPT 응답이 끊긴다" | 틀림. 끊긴 건 화면 렌더링 |
| "ChatGPT가 속도 제한을 걸었다" | 틀림. 짧은 주문은 정상 응답 |

**반례를 찾기 전에 원인을 말하지 마라**([[feedback_find_counterexample_first]]) — 메모리에 적어두고도 오늘 세 번 어겼다.

## 미해결 (2026-07-30 기준)

**긴 기사 주문이 ~300자에서 멈춘다.** 브라우저 화면에서도 거기서 끝나 있으므로 내 회수 문제가 아니다.
- 프로젝트 생성 **직후 첫 회는 979자·48초로 정상**이었다.
- 그 뒤 달라진 것: 지침 확장(1,263→1,709자), **프로젝트에 실패 조각·재촉이 누적**(전용 메모리라 새 대화에도 따라온다).
- 다음 확인: **프로젝트 밖 일반 대화**에서 같은 주문 1회 → 되면 프로젝트 오염, 안 되면 다른 원인.

## 작업 방식 (형 지적으로 교정)

**15단계 전체를 매번 돌리며 디버깅하지 마라.** 글자 하나 확인하려고 8~10분 파이프라인을 반복 실행한 것이 토큰·시간 낭비의 주범이었다.
→ `probe_write.mjs` 처럼 **고칠 단계만 30~60초로** 돌리고, 통과한 뒤에 뒤 단계를 붙인다.
