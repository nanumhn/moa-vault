2026-09-06 아투 조사에서 **같은 모양의 결함을 하루에 네 번** 만났다. 서로 다른 시스템인데 병이 같다.

| 어디 | 돌긴 도는데 | 세어지지 않은 이유 | 결과 |
|---|---|---|---|
| 아투 QA 게이트 | 기관 행위 검사 | `skipped=true` 로 판정 보류 → `ok:true` 로 기록 | 오탐도 정상도 구분 안 됨 |
| 회귀 테스트 | 케이스는 실행됨 | 테스트가 `ok` 만 보고 `skipped` 를 안 봄 | 구 코드에서도 통과 |
| `gate-heading-bleed` | 15건 다 통과 | 출력이 `전부 통과` 라 `\d+ passed` 패턴에 안 걸림 | 집계에서 "출력 없음" |
| `qa-minlen`·`qa-skipped` | 자체 하네스로 25건 통과 | `bun test` 러너는 `Ran 0 tests` 로 봄 | 일괄 실행 시 조용히 누락 |

**공통 구조**: 실행층과 판정층이 다른 곳을 본다. 실행은 성공하는데 **그 성공이 집계되는 경로가 끊겨 있다.** 끊긴 자리는 실패로 안 보이고 **초록불이나 침묵**으로 보인다 — 그래서 아무도 안 본다.

**어떻게 알아채나**
- 숫자가 **예상보다 작으면** 의심한다. "12개 파일인데 왜 11개만 세어졌지"가 신호다. 나는 187 vs 202 에서 이걸 놓쳤다.
- "통과"를 볼 때 **통과 옆의 상태 플래그**를 같이 본다. `ok` 만 보지 말고 `skipped`·`Ran N tests`·건수를 함께 읽는다.
- **일부러 깨뜨려 본다.** 구 코드로 되돌렸을 때 테스트가 실패하지 않으면 그 테스트는 아무것도 안 지킨다(2026-09-06 실측으로 확인).

**고치는 쪽**: 출력 형식을 표준에 맞추는 것이 실제 수리다. 내 집계 도구만 고치면 다음 사람이 같은 자리에서 또 놓친다 — 제나가 `gate-heading-bleed` 출력을 `N passed / N failed` 로 통일한 뒤 내 원래 명령이 그대로 202를 읽었다.
