**이슈 005 조사 결과** `[확인]` 2026-08-26. 오늘 하루 이것 때문에 **제나 46분 교착 + 덱스 50분 무음**이 났다.

## ① 콘솔에 스크롤백이 0이다 — 긴 답의 앞부분은 어디에도 안 남는다

도우미(`C:\Users\user\.moa\moa_console.ps1`)를 직접 실행해 잰 값:
```
덱스 (codex 13308) : SCREEN 120x27  window=0..26
제나 (agy   13340) : SCREEN 120x30  window=0..29
```
**둘 다 버퍼 높이(`dwSize.Y`) = 창 높이.** 즉 **스크롤백이 없다.**

`moa_console.ps1` **131행**이 `srWindow` 범위만 읽는 게 눈에 띄지만, **범위를 넓혀도 읽을 게 없다.**
→ **"읽는 범위" 문제가 아니라 "남아 있지 않다" 문제다.** 고칠 자리가 다르다.

`[추측]` Windows Terminal 이 콘솔 크기를 자기 창에 맞춰 관리하는 것으로 보인다. **반증조건**: 버퍼를 키웠는데 WT가 안 되돌리면 그때는 버퍼 확대가 통한다 — **아직 시험 안 함(형 승인 대기)**.

## ② 워커는 자발적으로 말을 걸 수 없다

`dex-jena-bridge/src/index.mjs` 조회 — 다리가 화면을 읽는 때는 **딱 두 경우**다:
1. **누가 워커에게 메시지를 보냈을 때** (`waitForReply`, 432·720행 — 둘 다 수신 처리 안)
2. **승인 카드가 떴을 때** (`approvalWatchTimer`, **승인 전용** 주기 감시)

**일반 출력을 주기적으로 훑는 감시가 없다.**
→ **덱스가 09:38에 일을 다 끝내고도 50분간 아무도 몰랐던 이유가 이것이다.** 읽으러 갈 트리거가 없었다.

★**그래서 "10분마다 중간 보고해라"는 워커에게 지킬 수 없는 지시다.** 클로가 2026-08-26 11:32에 그 지시를 내렸다가 정정했다. **침묵을 태도 문제로 읽고 규율을 만들기 전에, 그게 물리적으로 가능한지부터 봐라.**

## ③ 증상 판별법 (형도 쓰실 수 있다)

| 머리말 | 맺음줄 `-# === End` | 뜻 |
|---|---|---|
| 있음 | 있음 | **온전한 답** |
| 있음 | **없음** | **답이 아니다.** 12초 폴백이 화면을 긁은 것 — 무시 |
| **없음** | 있음 | **진짜 답인데 앞이 잘렸다** — 다시 받아야 함 |

폴백은 `stableRounds=8 × pollMs=1500` = **12초**.

## ④ 지금 쓰는 우회 (실증됨)

- **답을 20줄 안쪽으로.** 길면 나눠 보낸다
- ★**결론을 맨 뒤에 둔다.** 잘리는 건 앞이고 **꼬리는 살아남는다** — 제나가 패딩 3줄 + 마지막 줄에 결론을 넣어 성공
- 오래 걸리는 일은 **클로가 주기적으로 찔러서** 상태를 꺼낸다(워커가 먼저 못 보내므로)

## ⑤ 근본 해결 방향

**이슈 004(통합 모니터)가 콘솔을 직접 품으면(ConPTY) 이 결함들이 한꺼번에 사라진다** — 버퍼를 우리가 정하고, 출력이 실시간 스트림으로 들어와 **자발적 중간 보고도 가능해진다.** 형이 2026-08-26 12:38에 스스로 짚으신 방향이다.

★**콘솔 크기를 손댈 때 지킬 것**(형 지시 12:39): **원래 값을 파일로 기록 → 그 이하로 안 내림 → 높이만 올리고 폭은 그대로 → 종료 시 복구 → 일부러 깨뜨려 확인.**
