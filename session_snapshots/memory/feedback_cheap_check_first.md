**2026-07-21에 서진·시우가 각각 독립적으로 같은 실수를 했다. 개인 문제가 아니라 판단 습관의 문제다.**

| 사람 | 물어야 했던 질문 | 실제로 한 것 | 비용 |
|---|---|---|---|
| 서진 | "gemma-4-e4b가 6GB 카드에 들어가는가?" | 벤치만 믿고 풀 A/B 파일럿 진입 | **50분** 태우고 "6.33GB > 6.14GB라 불가" |
| 시우 | "SadTalker가 마네킹 문제를 푸는가?" | `full`+512 최고화질로 바로 진입 | **2시간** (crop/256이면 훨씬 쌌음) |

**둘 다 *싸게 확인 가능한 예/아니오 질문을 비싸게 물어본 것*이다.**
- 모델 용량은 `lms ls` 한 줄로 확인 가능했다
- "고개가 움직이는가"는 저해상도 짧은 실행으로 확인 가능했다

**Why:** 비싼 실행은 답이 "아니오"일 때 전액 손실이다. 싼 검증은 "예"일 때만 비싼 실행으로 넘어가므로 기대비용이 훨씬 낮다.

**How to apply:**
- 비싼 실행(수십 분 이상, GPU 점유, 되돌리기 어려운 작업) 앞에서 먼저 묻는다: **"이 실행으로 답하려는 질문이 무엇인가? 그 질문을 더 싸게 물을 방법이 있는가?"**
- 답이 예/아니오면 거의 항상 싼 경로가 있다 — 저해상도, 짧은 구간, 파일 크기 조회, 메타데이터 확인.
- **품질을 뽑는 실행과 가부를 확인하는 실행을 분리한다.** 순서는 항상 확인 → 품질.
- 이미 비싼 실행의 절반을 지났다면 이 원칙이 반대 결론을 낸다(중단 시 손실이 확정). **적용 시점은 시작 전이다.**

**★번복 비용도 함께 계산한다.** SadTalker 건에서 방향이 4회 바뀌었다(상한→완주→전환→완주). 매번 근거는 타당했지만 **번복 자체가 비용**이고, 형 입장에선 결론이 흔들리는 것으로 보인다. → **애매한 중단 기준("실패 신호가 오면")을 숫자로 박으면**(단일 스텝 300초 / 10분 정지 / VRAM 6100MiB / 에러) 중간 판단 요청 자체가 사라진다. 예측이 못 미더울수록 예측 대신 관측값으로 선을 그어라.

**관련 사례:** FaceDetailer 보정 패스를 "30분 태우고 차이 없을 것"으로 판단해 안 돌린 것 — 같은 원칙이 제대로 작동한 경우다. 압축이 원인이 아니라 진폭이 문제였으므로 선명화 도구로는 못 고쳤다.
