**`qa-gate.mjs`의 근거 대조는 ①큰따옴표 직접인용 ②숫자 토큰 두 가지만 본다.** 창작이 평서문 주장으로 들어가면 두 검사 모두 "대조 대상 없음"으로 ✅를 준다.

2026-07-28 실측 — blog-post_27 재생성 2회가 모두 이렇게 통과했다:
```
✅ 수치 근거 대조 (구체 수치 없음)
✅ 인용 근거 대조 (직접인용 없음)
```
그러면서 본문에는 `국회 국방위원회 예산 증액 논의`, `한국 자동차 업계가 패트리엇 기술 협력`, `고도 1만5천미터` 같은 근거 없는 주장이 들어 있었다. 2026-07-27에 인용·수치 대조를 넣어 막은 사고가 **문법만 바꿔 그대로 재발**한 것이다. 같은 증상이 라이브 `blog-post_28`에도 있다(두 절이 거의 같은 문장).

**로컬 qwen2.5-7b-instruct 생성 한계 (같은 날 실측):**
- 근거를 두껍게 주면 **모델에 도달하지 못한다** — `evidenceBudget`이 5,142자를 약 915자로 자른다. LM Studio가 CONTEXT 8192 · **PARALLEL 4**라 요청당 실효 한도가 2,000자대. 다출처를 모아도 1/5만 본다.
- 얇고 정확하게(검증된 사실 13줄) 주면 **반영률 13개 중 1개**, 빈자리를 채우려고 산업별 문단을 **업종명만 바꿔 완전 복제**하고 새 사실을 창작한다.
- 고유명사도 깨진다(`패트리엇` → `패트리오티아`).
→ 근거 품질을 올려도 생성 품질이 안 따라온다. 파이프라인 산출물을 믿기 전에 **평서문 주장까지 대조하는 검사**가 필요하다.
