아투 쇼츠는 블로그 글이 **그날(KST) 날짜 + publishedAt** 일 때만 만든다. 없으면 **12분 기다리고 건너뛴다** — 이건 설계대로다(공개 안 된 글로 쇼츠를 내면 설명란 링크가 죽으니까).

**사고**: QA 게이트에 걸린 글은 사람이 풀어줘야 하는데 실측 해제까지 **1시간 19분**이 걸렸다. 12분 대기로는 원리적으로 못 잡는다. 2026-08-19은 오전·저녁 **둘 다** 이렇게 날아가 하루 0개였고, 2026-08-17 오전에도 같은 일이 있었다. 형이 "오늘 오전 아투 쇼츠 발행 안 되었니?"라고 **13시간 뒤에 물어봐서** 알았다.

**왜 아무도 몰랐나 (핵심)**: 건너뛴 실행은 `exit=0`이다. 실패 알림은 코드≠0일 때만 울렸고, 건너뛴 실행은 디스코드 카드도 안 올려서 `MoaAtzReportWatchdogExternal`도 볼 게 없었다. **성공도 실패도 아닌 "아무것도 안 함"이 감시 사각지대였다.** [[reference_qa_gate_rule_inversion_blindspot_2026-08-07]] · [[feedback_verify_before_alarm]] 와 같은 계열.

**수리(완료)**: `shorts_scheduled.ps1`이 "실행됐는데 아무것도 안 올림"도 알린다. 그 실행이 append한 로그 구간만 되읽어 `youtube.com/shorts/` 마커로 판정. ★함정: bun 출력이 UTF-16이라 ASCII 사이에 NUL이 껴서 순진한 `-match`는 무조건 실패한다 — ASCII 디코드 후 NUL 제거 필요. 보류큐 cron(⑤)에도 "발행했으면 그 슬롯 쇼츠까지 이어서 돌린다"를 넣었다. 상세 절차는 `session_bootstrap.md` ⑤ 항목.

**교훈 2개**
- **exit code 0 ≠ 일이 됐다.** 원장(`publish_ledger.jsonl`)이나 실제 산출물로 확인해야 한다. 이번에도 복구 빌드가 exit=0으로 끝났지만 그건 아무 의미 없었고, 원장의 `status=published` + 유튜브 재조회 `status=PUBLIC`으로 확인했다.
- **게이트가 "인용 조작"이라고 잡아도 먼저 원문과 대조하라.** 실측 2건 다 지어낸 게 아니라 원문의 괄호(`이것(한미 연합훈련 축소)이`)나 소제목 축약 때문에 전체 문자열 대조가 깨진 것이었다. verbatim으로 되살리면 통과한다.

★블로그 공개(`run.mjs --from=...`)는 클로 세션에서 하네스 분류기가 막는다(2026-08-19 실측). 우회하지 말고 형에게 `!` 붙인 명령을 드릴 것. 쇼츠 빌드는 안 막힌다.
