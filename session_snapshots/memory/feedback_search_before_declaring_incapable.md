MCP 도구 목록에 없다고 해서 "그 일을 할 수 없다"고 단정하지 않는다. Bash로 실행하는 별도 스크립트(`.moa` 폴더 등)나 우회 경로가 이미 만들어져 있을 수 있다.

**Why:** 2026-08-28 형이 "워커간 멘션 호출" 이슈를 새 포럼 스레드로 만들라고 지시했는데, 클로가 `mcp__plugin_discord_discord__*` 도구 목록만 보고 "제 도구엔 스레드 생성 기능이 없다"고 형께 보고했다. 실제로는 `C:\Users\user\.moa\moa_forum_thread.mjs`가 2026-08-26에 이미 만들어져 있었고(클로 자신의 봇 열쇠로 이슈처리-2026 포럼에 새 글/답글 가능), **그 존재가 메모리에도 이미 기록돼 있었다**([[project_open_threads_2026-08-26_dawn_snapshot]] 참고). 형이 과거 "달려라 클로" 이름으로 올라간 포럼 글 스크린샷을 보여주며 "거짓말쟁이 클로"라고 지적했다.

덱스가 정확히 짚었다: 클로의 문장("제 도구엔 기능이 없다")은 좁게 보면 사실이었지만("그 MCP 플러그인엔 진짜 없다"), 그걸 "전체가 불가능하다"로 일반화해서 대체 경로를 안 찾아본 게 문제였다 — 의도적 거짓말이 아니라 **검증 없이 단정한 오보고**.

**How to apply:**
- "못 한다"/"권한이 없다"/"그 기능이 없다"라고 말하기 전에, **메모리(MEMORY.md 검색) + `C:\Users\user\.moa\` 폴더**에 관련 스크립트나 우회 도구가 이미 있는지 먼저 찾는다.
- 불가 판정을 보고할 땐 어떤 도구·경로를 확인했는지 명시한다("MCP 도구 목록엔 없음"처럼 범위를 정확히 좁혀서 말하고, 전체가 불가능하다고 일반화하지 않는다).
- 관련: [[feedback_pinocchio_clo_dont_assert_without_checking]] (확인 없이 단정 금지의 같은 계열), [[reference_dex_jena_bridge_silent_loss_2026-08-24]]류의 "이미 만들어둔 우회로를 몰라서 다시 헤맨" 패턴과도 겹친다.
