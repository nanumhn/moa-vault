**2026-08-24 확진.** 덱스가 공통 규칙을 읽었는데 `# 紐⑥븘 ? 怨듯넻 ?섏튃` 로 깨졌고, **그 상태로 형께 "적용됐습니다"라고 답했다.**

**원인**: `Get-Content` 는 **BOM 없는 UTF-8** 을 CP949로 읽는다. `-Raw`·`-LiteralPath` 를 붙여도 안 고쳐진다(둘 다 재현). **`-Encoding UTF8` 을 명시해야** 한다.

**인과 확정 방법(좋은 절차)** — BOM 없는 백업본을 **덱스에게 직접 읽혀** 재현시켰다. 내 프로세스로 잰 게 아니라 **실제 소비자로** 쟀다.

**범위 — 덱스만의 문제가 아니다**
- `moa-vault` `.md` 638개 중 한글 포함 633개, **BOM 없는 것 631개.** 2026-08-24 수리는 이 631개를 고친 게 아니라 **"덱스가 잘못 읽는 것"** 을 고친 것이다.
- `C:\Users\user\.moa` `.ps1` 45개 중 한글 포함 27개, **BOM 없음 7개** — `moa_cli_window.ps1` 포함. **잠재 위험이며 실제 오작동은 안 쟀다**(그 파일은 오늘 실제로 창을 띄웠다).
- ★**한글이 어디 있느냐로 증상이 갈린다**: 출력문 안이면 "글자만 깨짐", **문자열 리터럴 안이면 괄호 짝이 깨져 실행 자체가 실패**한다(서지안이 직접 걸렸다).

**How to apply**
- 한글이 든 `.ps1` 은 **UTF-8 BOM 으로 저장**한다([[reference_moa_healthcheck]] 의 기존 교훈과 같다).
- 파일을 읽을 땐 **PowerShell 말고 전용 읽기 도구**를 쓴다. 제나는 자체 Read 도구를 써서 **같은 파일을 멀쩡히 읽는다** — 결함은 덱스(PowerShell 경로) 전용이다.
- ★**깨진 내용으로 답하지 마라.** 못 읽었으면 못 읽었다고 말한다. **11:25 사고의 진짜 원인은 미해명이다** — 대조군에서 덱스는 새 규칙 없이도 깨짐을 보고했다. 규칙 부재가 원인이 아니었다.
- 파이썬으로 파일 크기를 잴 때 텍스트 모드로 읽으면 **CRLF가 LF로 접혀 줄 수만큼 작게 나온다**(15,753 vs 실제 15,930). **크기는 디스크 실제 바이트로만 재라** — 하루에 두 번 틀렸다.
