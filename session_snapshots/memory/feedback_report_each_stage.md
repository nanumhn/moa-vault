여러 라운드를 거치는 작업(특히 completion-gate 반려-재제출 루프처럼 내부적으로 여러 번 왕복하는 경우)은 최종 결과만 한 번에 보고하지 말고, **각 단계(라운드)가 끝날 때마다 짧게 보고**해야 한다.

**Why:** 2026-08-08 네이버 블로그 SaaS 페이즈1 설계에서 qa-lead-jian 검수가 7라운드 연속 반려되는 동안(각 라운드가 실제 동시성 버그를 잡아내는 정당한 반려였음) 클로가 중간 진행상황을 거의 보고 안 하고 내부적으로만 계속 주고받았다. 형이 "중간중간 단계마다 보고서 정리해"라고 명시 지시함. [[project_naver_blog_saas_2026-08-08]]

**How to apply:** completion-gate PASS/FAIL 루프, 여러 에이전트가 순차로 주고받는 작업, 긴 백그라운드 작업 등에서 라운드가 끝날 때마다(FAIL이어도) 1~3줄로 "이번 라운드에 뭘 고쳤는지/뭘 새로 발견했는지"를 형에게 보고할 것. FAIL 내용 자체를 형에게 넘기지 말라는 규칙([[project_moa_open_threads]] 계열의 "FAIL은 형을 거치지 않는다")과는 별개 — 반려 상세는 내부에 남기되, "진행 중이다/이만큼 왔다"는 진행상황은 매 라운드 짧게라도 보고해야 한다. [[feedback_reporting_cadence]](3-tier: 마일스톤·10분무음컷·이슈즉시)의 마일스톤 단위를 "라운드 1개"로 좁혀서 적용하면 됨.
