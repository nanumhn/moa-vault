돌아가는 화면은 **워킹트리**를 보여준다. 커밋도 아니고 라이브도 아니다. 그걸 근거로 "있다/없다"를 단정하면 틀린다.

**★네 가지는 서로 다른 시점을 가리킨다 — 섞지 말 것**
`실행 중인 화면(워킹트리)` ≠ `커밋` ≠ `푸시된 브랜치` ≠ `라이브(배포된 빌드)`
2026-08-20에 세 번 오판했고 전부 이 넷 중 둘을 같은 것으로 본 탓이었다.

**Why:** 2026-08-20 하루에 같은 원인으로 **양방향 오판**이 났다.
- 오전 — 에이전트가 리팩터링 중이라 파일이 반쯤 깨져 있었는데, 그 상태를 dev 서버가 집어 `POLARITY_MAX is not defined`가 떴다. 하마터면 **존재하지 않는 버그**를 형에게 보고할 뻔했다. `git show HEAD:<파일>`로 커밋에는 멀쩡히 있는 걸 확인해서 걸렀다.
- 저녁 — 반대로, 에이전트가 워킹트리에 넣던 티저를 HMR이 집어 화면에 떴고, 나는 그게 커밋 내용인 줄 알고 **"이미 있으니 작업 멈추라"**고 잘못 지시했다. 실제로는 커밋에 없었고 라이브에도 없었다.

**How to apply:**
- 화면에서 뭘 보고 판단하기 전에 **`git show <커밋>:<파일>`** 또는 `git status`로 커밋 상태를 먼저 확인한다.
- 특히 **에이전트가 작업 중일 때** dev 서버를 띄우지 말 것. 띄워야 하면 그 사이 파일이 바뀔 수 있음을 전제로 본다.
- 에이전트에게도 규칙으로 걸어라: **"완료 = 손 뗀 상태(커밋했거나 되돌렸거나)"**, 추가 작업이 생기면 착수 전에 "아직 작업 중"이라고 먼저 알릴 것. 이 규칙을 건 뒤 혼선이 줄었다.
- 내가 포트를 죽이거나 서버를 내릴 때도 **작업 중인 에이전트에게 먼저 알린다**(Prisma DLL 잠금 때문에 자주 필요하다).
