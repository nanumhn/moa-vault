2026-08-15 을지로 편 발행 실패(NAVER_LOGGED_OUT) 재시도 작업 중, 클로가 "운영 DB에 직접 접근"이 auto-mode 권한 클래시파이어에 막혀서 형에게 터미널로 직접 SSH+DATABASE_URL 조회를 안내했다. 형이 그 명령 실행 결과를 스크린샷으로 캡처해 디스코드에 올렸는데, 화면에 `DATABASE_URL`/`DATABASE_URL_UNPOOLED` 값(Neon Postgres 계정+비밀번호+호스트 전체)이 평문으로 그대로 찍혀 있었다.

**즉시 대응**: 클로는 그 값을 답장에 다시 옮기지 않았고(추가 노출 방지), 형에게 "이후 Neon 콘솔에서 비밀번호 로테이션 권장"만 안내함. 작업(재시도) 자체는 먼저 마치고 로테이션은 나중으로 미룸(형 판단).

**Why**: 기존 규칙([[feedback_no_falsehood_double_check]] 인접 규칙 "API 키는 메모리·transcript·vault·git 어디에도 절대 X")은 클로 자신이 키를 직접 타이핑/저장하는 경로만 상정했는데, 이번 건은 **형이 터미널 결과를 스크린샷으로 캡처해 옮기는 경로**로 새는 사례였다 — 클로가 직접 안 적어도, 운영자에게 명령 실행을 위임하면 그 결과 화면 자체가 새로운 유출 경로가 될 수 있다.

**How to apply**: 앞으로 형에게 "터미널에서 직접 실행해주세요"로 시크릿을 다루는 명령을 위임할 때는, 처음부터 "결과 화면(특히 비밀번호 부분)은 캡처해서 올리지 말고 텍스트로 성공/실패만 알려달라"고 미리 못박을 것. 이미 노출된 경우엔 즉시 로테이션 권고(이번처럼)하고, 완료됐는지 다음 세션에서 확인.

**2차 노출(같은 세션, 몇 분 뒤)**: 스크린샷 지적 직후에도 형이 다음 명령어(`$env:DATABASE_URL = "..."`) 전체를 이번엔 **평문 복사가능 텍스트로** 채팅에 그대로 붙여넣음 — 스샷보다 더 나쁨(그대로 복사·검색 가능). 클로는 답장에 값을 다시 옮기지 않았고, 형에게 그 메시지 직접 삭제 요청(클로는 타인 메시지 삭제 권한 없음) + 로테이션 필요성을 더 강하게 재강조함. **패턴**: 한 번 경고해도 작업에 몰입하면 같은 실수가 반복될 수 있다 — 다음엔 애초에 "복사/붙여넣기도 하지 마시고 터미널에만 입력해주세요"까지 먼저 말할 것.
