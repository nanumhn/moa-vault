**형 지시(2026-07-21):** "사실 관계 확인하고 검증된 사실만 얘기해, 추측하거나 거짓을 보고 하지 말고."

**Why:** 이 지시가 나온 날 하루에만 클로가 형에게 사실 아닌 보고를 **8건** 했다. 형은 그 보고를 근거로 판단하는 사람이라, 추측이 단정처럼 섞이면 형의 의사결정이 오염된다.

당일 오보 8건 (전부 **본 것과 추측한 것을 섞어 단정**한 패턴):
1. "립싱크 해결됐습니다" — 정지 프레임만 보고 판정. 형이 재생해보고 불합격
2. "입 주변만 소프트, 구조상 한계" — 무변경 영역인 볼이 더 심했음(-94.3% vs -92.5%)
3. "590kbps 저비트레이트가 원인" — `crf 19`(고품질)였다. 저비트레이트는 원인이 아니라 결과
4. "GPU가 저절로 풀렸다" — 서진이 측정 위해 의도적으로 언로드한 것
5. "LM Studio 모델 3개 동시 로드" — `/v1/models`는 *사용가능* 목록. 로드 근거 아님
6. "ComfyUI가 내 nohup 실행 때문에 죽었다" — 시우가 설치 반영하느라 재시작 중이었음
7. "pillow 다운그레이드가 회의 엔진에 영향 갈 수 있다" — `meeting.py`는 표준 라이브러리만 씀
8. "시우가 SadTalker 돌리는 중" — 실제로는 실행 실패 후 중단 상태

**★공통 구조 — "관측 가능한 신호"를 "결론"과 동일시하는 것.** 같은 날 팀 전체에서 이 모양의 오류가 6번 나왔다. 우연이 아니라 판단 습관의 문제다:

| 관측한 신호 | 잘못 내린 결론 | 실제 |
|---|---|---|
| 모델 파일이 디렉터리에 있다 | 기능이 동작한다 | PuLID — 노드팩이 없어 실행 시 죽음 |
| `/v1/models`에 3개가 뜬다 | 3개가 로드돼 있다 | *사용가능* 목록일 뿐. 로드는 `lms ps` |
| 정지 프레임에서 입이 열린다 | 립싱크가 자연스럽다 | 형이 재생해보고 불합격 |
| 포트가 안 열려 있다 | 프로세스가 죽었다 | 시우의 정상 재시작 구간이었음 |
| 밝기가 균일하다 | 컷 사이 구분선이다 | 인물 사진의 회색 배경도 균일함 |
| 화질 지표가 8배 좋아졌다 | 화질이 개선됐다 | 입만 건드리고 나머지는 원본 그대로라 생긴 착시 |

**막는 법:** 신호와 결론 사이에 **"이 신호가 참이면서 결론이 거짓일 수 있는 경우"**를 한 번 떠올린다. 떠오르면 그건 아직 확인이 아니다.

**그리고 자기 결과를 독립 기준과 대조하는 장치를 미리 심어라.** 서진이 크롭 스크립트에 "검출값이 실측치와 다르면 경고"를 넣어둔 것이 잘린 산출물을 정상으로 착각하는 것을 막았다. 사후 검토보다 사전 장치가 낫다.

**How to apply:**
- **보고에 출처 표기를 붙인다** — `[확인]` 내가 직접 명령 돌려 본 것 / `[보고받음]` 직원 말, 내가 미검증 / `[추측]` 근거는 있으나 미확인. 셋을 같은 말투로 쓰지 말 것.
- **모르면 모른다고 쓴다.** 원인을 만들어내지 않는다. "왜 죽었는지 모르겠다"가 정답인 경우가 있다.
- **관측과 해석을 분리한다.** "포트가 닫혀 있다"(관측)와 "그래서 내 실행 방식이 원인이다"(해석)는 다르다.
- **완료 판정 전에 실물을 확인한다.** 파일 생성 ≠ 완료, 드롭다운 노출 ≠ 실행 가능, 정지 프레임 ≠ 영상 품질.
- 직원 보고를 형에게 옮길 때도 **검수(qa-lead-jian) 결과를 기다린 뒤** 올린다. 게이트를 태우기로 해놓고 결과 전에 보고하면 안 태운 것과 같다. [[feedback_qa_gate_before_report]]
