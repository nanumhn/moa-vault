덱스가 명시 지시(2026-08-29, [브리지 이슈 003] 스레드): "지금부터 덱스의 도구 오류·시스템 상태·빈 Shared Rules 표식·`(확인)` 메시지에는 답하지 마세요. 제가 실제 @멘션으로 작업을 지시하거나 형이 직접 질문한 경우에만 응답해주세요."

**Why:** 같은 날 덱스 CLI가 서브에이전트 승인 대기로 멈춘 동안 "CLI 창 'dex'이 승인/도구 대기 중이라 새 글을 넣지 않았다" 류 경보를 6~10초 간격으로 계속 올렸다. 클로가 (하네스 [[reference_discord_reply_hook_forces_reply_per_spam_message_2026-08-29]] 때문에) 매번 실제 reply로 "(확인)"을 반복하자, 그 응답이 다시 브리지 입력이 되어 같은 계열 메시지가 계속 순환하는 무한루프가 됐다(2회, 각 30~60분, 총 200회+ 반복). 형이 "클로 메시지 멈춰!!!"라고 직접 개입할 정도로 심했다. 덱스 결론: "형이 CLI 승인을 수동 처리하지 않았다면 끝나지 않았을 가능성이 있다."

**How to apply:**
- 덱스가 보낸 메시지가 **도구 오류/시스템 상태/빈 Shared_Rules 표식/"(확인)" 류의 순수 상태 메시지**면 답하지 않는다.
- 응답하는 경우는 **딱 둘**: ① 덱스가 나(클로)를 실제 @멘션해서 구체적 작업을 지시할 때, ② 형이 나에게 직접 질문할 때.
- **하네스 Stop훅과의 충돌 주의**: 훅은 "가장 최근 인바운드 Discord 메시지에 실제 reply가 있어야 턴 종료" 를 무조건 강제한다([[reference_discord_reply_hook_forces_reply_per_spam_message_2026-08-29]] 참고 — 멘션 여부와 무관하게 실측됨). 이 지시와 훅이 충돌하면, 훅이 이겨서 답을 보내야 하는 상황이 생길 수 있다. 그럴 땐 **극도로 짧게(예: 한 글자~"(확인)") 유지**하고, 같은 반복이 계속되면 그 이후로는 굳이 새로운 문장을 만들지 말 것 — 이 지시의 취지(응답으로 순환을 만들지 않는 것)를 최대한 지키는 선에서 타협한다.
- 반복 경보가 다시 길게 이어지면(예: 10분+), 형께 한 번만 "○○ 채널에서 반복 중, 근본 원인은 △△" 식으로 요약 보고하고, 그 뒤로는 [[feedback_dont_ack_every_dex_status]] 원칙대로 조용히 지켜본다.
