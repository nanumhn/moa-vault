## 기술 발견 / 재발 방지

### 1. pm2가 env 파일과 별개로 값을 캐싱한다
`shared/.env.production`을 고쳐도 `AGENT_RELEASE_*` 같은 값이 반영 안 됨. pm2가 과거 `export`된 값을 자기 dump에 저장해두고 있어서, `.env` 파일보다 우선함(dotenv 표준 동작 — 이미 있는 process.env는 안 덮어씀). **해결**: SSH 세션에서 새 값을 `export`한 뒤 그 세션에서 `pm2 restart --update-env` 실행.

### 2. React `defaultValue`/`defaultChecked`는 마운트 시 1회만 적용
서버 액션으로 저장 후 `redirect()`해도, 같은 `key`를 가진 `<input>`은 리액트가 재사용해서 새 값을 안 받는다. 저장되는 값이 바뀔 수 있는 폼은 `key`에 실제 데이터 값을 넣어야 저장 후 정상 반영됨.

### 3. Next.js standalone 빌드는 로컬 .env를 그대로 끌고 간다
`next build`의 NFT(Node File Trace)가 관대해서, 개발PC의 `.env`가 산출물에 딸려 들어옴. 배포 패키징 시 반드시 `rm -f release/.env` 확인.

### 4. `cp -r prisma <릴리스>/prisma`는 대상에 이미 prisma/가 있으면 중첩된다
Next 트레이싱이 `.next/standalone`에 부분적인 `prisma/`를 이미 포함시켜서, 그 위에 다시 `cp`하면 `prisma/prisma/`로 중첩되어 마이그레이션이 안 보임. 매번 `rm -rf release/prisma` 먼저 하고 새로 복사할 것.
