**폐기안:** "호스트별 최대 사이트맵 채택"(182p) — 담당자 스스로 "엄밀히는 179가 맞다"고 인정한 값이라 반려. 원리적으로도 한 호스트에 URL 집합이 다른 사이트맵 둘이 있으면 과소표기가 된다.

## 실무 함정 기록
- 이미지 CDN이 python urllib UA를 403 차단 → curl `-A "Mozilla/5.0"` 필요
- 검색 결과에 인물 얼굴 혼입 → 검색어로는 안 걸러진다
- 작가명 키릴 문자면 cp949에서 깨짐
- `apple`만 검색하면 과일 사과가 섞임 → 회사 맥락 단어 동반 필수
- 검색어를 섞어 던지면(`apple store iphone`) 결과가 희석돼 진짜 애플 사진이 안 나온다
- Flux는 cfg 1.0이라 네거티브가 약하다 → 글자·UI·인장은 **소재 선택 단계에서** 배제해야 한다
- GSC 사이트맵 응답의 `indexed`는 전부 0으로 온다(구글이 안 채움) → 쓰면 "색인 0" 오보

## 조직 운영 교훈
**이번 세션 실수 5건이 전부 같은 유형이었다: 확인할 수 있는 것을 확인하지 않고 실행/단정.**

세 사람(나·담당자·검수관) 모두에게서 같은 패턴이 나왔다. 개인 습관이 아니라 작업 방식의 구멍.

**completion-gate에 추가할 체크 2개:**
1. 코드·config·문서를 한 세트로 갱신했는가 (문서가 두 번 뒤처졌고, 둘 다 형이 읽는 매뉴얼이 실제 동작과 어긋나는 형태였다)
2. **제출물 안에 자기모순이 있는가** — 제출 메시지·주석·문서에 산출물 수치를 부정하거나 한정하는 문장("엄밀히는 X", "남은 오차")이 있으면 자동 반려. 담당자가 스스로 적은 한정어는 결함의 자백이다.

**사용 한도는 계정 공용이다.** 서브에이전트별 개별 한도가 아니라 5시간 롤링 계정 한도를 나눠 쓴다. 직원 여러 명을 동시에 오래 굴리면 메인 세션 몫까지 태운다. 한 명이 멈추면 "전체가 많이 썼다"는 신호로 읽어야 한다.

**역할 경계:** 검수관은 판정·권고·수용기준까지, 설계 결정은 팀리드. 검수관이 설계를 내고 스스로 통과시키면 독립검수가 무너진다. 단, 엇갈린 지시를 감지해 실행을 멈추고 올리는 건 검수관의 정당한 권한이다.
