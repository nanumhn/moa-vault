## 이번 세션에 배운 것 (다음 세션이 같은 실수를 안 하려면)

### 1. 검사 도구는 "우리가 적어 넣은 값"을 믿으면 안 된다
MOC 낡음 검사가 이틀 연속 "이상 없음" 오진을 냈다. 원인은 frontmatter 의 `updated:` **한 줄만** 읽은 것 — 그 값은 사람이 손으로 적는다.
→ **커밋·파일 변경이라는 바깥 증거와 대조**하게 바꿨다. 기준 시각은 MOC 의 **마지막 커밋 시각**(파일 mtime 은 일괄 편집에 다 바뀌어 못 쓰고, `updated` 날짜는 하루 단위라 "아침에 쓰고 오후에 일한 것"을 영원히 못 잡는다).
→ **"이상 없음"과 "검사를 안 했음"을 다른 출력으로 분리**했다(`NOSOURCE`/`LOOKUP-FAIL`). 조회 실패를 부재로 읽지 않기 위해서다.
→ **04:13 첫 자동 실행에서 실제로 k-saju 를 잡았다.** 옛 방식이면 통과했을 건이다.

### 2. 원인을 말하기 전에 돌려보라 — 이번에 세 번 뒤집었다
아투 삽화 원인을 "나라별 장면이 2개뿐"이라고 단정했는데, 그 표는 **폴백 경로**였고 주 경로는 LM 이었다. 코드 한 군데 훑고 말한 결과다.
심각도도 기사 1건(최악 회차)으로 "4개 중 3개 반려"라 했다가 6건 재측정에서 **25%** 로 정정했다.
→ **형이 "뭘 믿어야 할지 너무 혼란스럽네"라고 했다.** 정정이 문제가 아니라 **안 재보고 확신한 게** 문제다.

### 3. ★시간도 "쟀다"고 착각할 수 있다
백그라운드 대기(`run_in_background`)는 **나를 막지 않는다.** 9분 타이머를 걸어놓고 기다린 줄 알았지만 실제로는 즉시 다음 확인을 했다. 그래서 몇 분을 몇십 분으로 세어 **"한 장에 40~50분"이라고 보고했는데 실제 평균은 11분**이었다.
→ **시각이 필요하면 반드시 시계를 찍는다**(PowerShell `Get-Date`, 또는 페이지 안 `new Date()`). 감으로 센 시간은 측정이 아니다.

### 4. 대량 생산 전에 한 장으로 검증하면 16번 다시 안 해도 된다
타로 황제 카드가 **중국 사자상+곤룡포**로 나왔을 때 나머지 16장을 멈추고 형에게 물었다. 형 결재로 조선 관복 규칙을 넣고 재생성했다. 그대로 갔으면 16장에 같은 결함이 복사됐다.
같은 방식으로 **별·달**이 로마 숫자(XVII·XVIII)·세로형·어두운 배경으로 규칙 3개를 어긴 것도 그 자리에서 잡았다.

### 5. 배포 전 dry-run 이 하루치 게시를 살렸다
n8n 캐러셀을 **게시 노드만 끈 채** 돌려봤더니 `ExpressionError: "Get IG User ID" node has 1 item(s) but you're trying to access item 1`.
fan-out(슬라이드 5개) 뒤에 앞 노드를 `$node["X"].json` 으로 참조하면 **같은 인덱스**를 찾아 2번째부터 없다 → **`$('X').first().json`** 으로 6곳 교체.
→ 안 돌려봤으면 08-23 08:00 게시가 통째로 날아갔다.
