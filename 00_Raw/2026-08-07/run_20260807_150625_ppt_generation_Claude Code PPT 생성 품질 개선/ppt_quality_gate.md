# PPT 품질 게이트

작성: 박지원(QA) · 보완: 정도현(COO, 검수 반려 2·3·5·6번 반영)

## 인수 기준 (AC)

| ID | 기준 | 측정 방법 | 우선순위 |
|---|---|---|---|
| AC1 | 산출물이 편집 가능한 .pptx인가 | 확장자 `.pptx` + OOXML 구조 검사(zip 열림, `ppt/presentation.xml` 존재) | P0 |
| AC2 | 모든 차트·수치에 출처와 기준일이 있는가 | 차트 원본 JSON의 `source`·`asOf`가 비어 있지 않은지 검사 + 슬라이드에 출처 텍스트 상자 존재 확인 | P0 |
| AC3 | 슬라이드마다 시각 요소가 1개 이상인가 | 슬라이드별 shape 순회로 그림·차트·표 개수 ≥ 1. **장식 도형(컬러 바·구분선·배경 사각형)은 계수하지 않는다** | P0 |
| AC4 | 슬라이드 규격이 16:9인가 | `presentation.slide_width / slide_height` = 13.333in / 7.5in 인지 검사 | P1 |
| AC5 | 슬라이드당 텍스트 분량이 상한 이내인가 | 본문 불릿 3개 이하, 한 줄 60자 이하 | P1 |
| AC6 | 한글 텍스트 그래픽이 HTML/CSS 렌더 산출물인가 | 이미지 생성 로그에서 한글 포함 그래픽의 생성 경로가 렌더러인지 확인 | P1 |
| AC7 | .pptx 파일 용량이 한도 이내인가 | 파일 크기 ≤ 8MB, 이미지 1장 ≤ 500KB | P2 |

## P0 — 발행 차단 항목

- [ ] **출처·기준일 없는 수치 또는 차트가 1건이라도 있음** → 차단. 라벨을 달아 통과시키지 않는다.
- [ ] 산출물이 `.pptx`가 아니거나 OOXML 구조가 깨져 열리지 않음 → 차단.
- [ ] 시각 요소가 하나도 없는 슬라이드가 있음 → 차단. 장식 도형은 시각 요소로 세지 않는다. AC3의 목적은 텍스트만 있는 슬라이드를 막는 것이고, 컬러 바는 정보를 담지 않으므로 세면 규칙이 형해화된다.
- 이미지 조달에 실패한 본문 슬라이드는 이미지 자리를 표로 대체해 이 항목을 통과시킨다(비주얼 에셋 파이프라인 fallback 3번). 단색 배경으로 비워 내보내지 않는다.

> P0의 핵심은 첫 번째다. 회사 규칙은 "출처 없는 수치는 지어내지 않는다"이며, 이는 **차단** 규칙이지 표기 규칙이 아니다. `(예시)`·`(불명)` 같은 라벨을 붙여 통과시키는 경로는 두지 않는다. 라벨은 규칙을 지킨 것이 아니라 우회한 것이다.
> 템플릿에 넣는 더미 데이터는 예외가 아니라 **발행 대상이 아닌 것**으로 분리한다. 고객에게 나가는 파일에 들어가는 순간 P0가 적용된다.

## P1 — 경고 후 자동 보정

- [ ] 슬라이드 규격이 16:9가 아님 → 13.333in × 7.5in로 자동 보정 후 경고.
- [ ] 본문 불릿이 3개를 넘거나 한 줄이 60자를 넘음 → 초과분을 다음 슬라이드로 분리 제안하고 경고.
- [ ] 한글 텍스트가 들어간 그래픽이 이미지 생성 모델 산출물로 확인됨 → HTML/CSS 렌더로 재생성하고 경고. (이미지 생성 모델은 한글 글자를 제대로 렌더하지 못한다)

## 검사 대상

- 완성된 `.pptx` 파일 — python-pptx로 열어 슬라이드·shape을 순회한다.
- 차트 원본 JSON — `source`·`asOf` 필드를 검사한다. 슬라이드만 봐서는 출처의 진위를 알 수 없으므로 원본을 같이 읽는다.
- 슬라이드 원고(마크다운) — 텍스트 분량 상한 검사에 쓴다.

## 위반 시 조치

| 위반 | 조치 |
|---|---|
| 출처·기준일 없는 수치·차트 | 반려 (P0) — 출처를 채우거나 해당 차트를 제거하기 전에는 발행하지 않는다 |
| .pptx 아님 / 구조 깨짐 | 반려 (P0) — 생성 단계 로그를 확인해 재생성 |
| 시각 요소 0개 슬라이드 | 반려 (P0) — 해당 슬라이드에 이미지·차트·표 중 하나를 추가 |
| 16:9 아님 | 자동 보정 (P1) — 규격을 13.333in × 7.5in로 재설정 |
| 텍스트 분량 초과 | 자동 보정 (P1) — 슬라이드 분리 후 경고 |
| 파일 용량 초과 | 자동 보정 (P2) — 이미지 재압축 |

## 가장 흔할 실패 3가지

1. **출처가 슬라이드에는 찍혀 있는데 원본 데이터에는 없음** — 감지: 슬라이드 텍스트만 보지 말고 차트 원본 JSON의 `source`를 함께 대조한다. 텍스트 상자에 "출처: 내부 자료"처럼 적어두면 사람 눈에는 통과하지만 근거가 아니다.
2. **표지·섹션 슬라이드가 이미지 한 장이라 텍스트 검사에 안 걸림** — 감지: 이미지로 얹은 슬라이드는 원고 마크다운 쪽에서 문구를 검사한다. .pptx만 보면 텍스트가 0으로 잡혀 조용히 통과한다.
3. **차트 기준일이 데이터 수집일이 아니라 파일 생성일로 찍힘** — 감지: `asOf`가 빌드 실행일과 같은 값이면 의심 대상으로 표시하고 사람 확인을 요청한다.

## 사람이 봐야만 하는 항목 (자동화 불가)

- **디자인이 실제로 화려해 보이는가** — 규격을 다 지켜도 밋밋할 수 있다. 스크립트는 요소의 존재만 세지 배치의 완성도를 못 본다.
- **이미지가 슬라이드 내용과 맞는가** — 배경 이미지가 문맥과 무관해도 "이미지 1개 있음"으로 통과한다.
- **출처가 실재하고 그 수치를 실제로 담고 있는가** — 형식 검사는 `source` 필드가 비었는지만 본다. 링크가 살아 있는지, 그 문서에 그 숫자가 있는지는 사람이 확인한다.
- **고객사명·업종 등 제안서 고유 정보가 정확한가** — 템플릿 치환 누락은 형식상 아무 문제가 없어 보인다.
