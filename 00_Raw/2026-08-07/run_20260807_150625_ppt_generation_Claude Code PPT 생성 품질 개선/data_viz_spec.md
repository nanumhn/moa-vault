# 데이터 시각화 규격

## 차트 유형별 사용 기준
```markdown
## 차트 유형별 사용 기준
| 차트 | 언제 쓰나 | 쓰면 안 될 때 |
|---|---|---|
| 막대 | 구체적인 카테고리별 비교를 위해 (예: 판매량 비교) | 대수적 관계가 없는 데이터, 연속적인 범위 표현을 위한 경우 (예: 날씨 온도) |
| 꺾은선 | 시간 기반의 변화 추세를 나타낼 때 (예: 주간 매출 추이) | 단순한 분포나 카테고리를 보여줄 때 (예: 고객 연령 구분) |
| 비교/구성 표현 (파이 차트) | 부분과 전체 사이의 관계를 나타낼 때 (예: 시장 점유율) | 구체적인 값이 아닌 비율만을 표시해야 할 경우 (예: 2023년과 2024년 매출 비교) |
```

## 데이터 입력 형식
```json
{
  "title": "...",
  "chartType": "bar" | "line" | "pie",
  "labels": ["..."],
  "series": [{ "name": "...", "values": [0, 0] }],
  "source": "...",
  "asOf": "YYYY-MM-DD"
}
```

## 수치·출처 표기 규칙
1. 모든 수치는 실제 데이터가 아니라면 "(예시)"로 표기한다.
2. 출처 정보는 각 차트 아래에 반드시 포함되며, 출처가 없으면 "(불명)"으로 표기한다.
3. 기준일은 차트 삽입 시점과 동일해야 하며, 날짜 형식은 YYYY-MM-DD로 표기한다.

## 출처 없는 수치 차단 장치
- 검사 항목: 데이터 입력 JSON에서 "source"가 비어 있는지 확인.
- 위반 시 조치: 자동으로 "(불명)"으로 대체하고, 검사 메시지를 출력하여 개발팀에 알림.

## 데이터가 없거나 불충분할 때
- 대체 시각화: 테이블 또는 텍스트로 데이터를 전달.
- 절대 하면 안 되는 것: 빈 차트를 삽입하지 않음. 필요한 정보가 없으면 대체 시각화를 제공.

## 차트 시각 규격
| 항목 | 기준 |
|---|---|
| 색상 수 | 4개 이내로 사용, 일관된 테마에 맞추어 선택 (예: 회사 로고 색상) |
| 범례 위치 | 차트 왼쪽 아래 또는 위쪽 (예: 막대 차트에서는 왼쪽 아래, 꺾은선 차트는 위쪽) |
| 축 레이블 | 명확하고 간결하게 작성, 단위 포함 (예: 시간 - 분, 판매량 - 수) |
| 데이터 라벨 | 필수적으로 표시, 숫자는 2자리 이상으로 표현 (예: 100, 500) |

## 차트 제목 규격
| 항목 | 기준 |
|---|---|
| 길이 | 최대 15글자 이내로 작성 (예: "2023년 Q4 매출" 대신 "Q4 2023 매출") |
| 명확성 | 구체적으로 설명하며, 키 메시지를 전달 (예: "매출 증가 추세" 대신 "2023년 Q1부터 Q4까지 매출 20% 상승") |

## 차트 크기 규격
- 막대 차트: 최소 너비 500px, 높이 300px (예시)
- 꺾은선 차트: 최소 너비 600px, 높이 400px (예시)
- 파이 차트: 반지름 150px (예시)

## 색상 선택 규격
| 항목 | 기준 |
|---|---|
| 일관성 | 동일한 테마 내에서 일관된 색상을 사용 (예: 회사 로고 색상) |
| 명암 대비 | 충분한 명암 대비를 유지하여 차트가 가독성을 높임 (예: 주요 데이터는 밝은 색, 보조 데이터는 어두운 색) |

## 범례 위치 규격
- 막대 차트: 왼쪽 아래 또는 위쪽에 배치하여 전체 차트와 잘 어울림.
- 꺾은선 차트: 위쪽에 배치하여 주요 흐름을 명확히 보여주면서 차트 공간을 최적화.

## 축 레이블 규격
- 시간 축: 년, 월, 일 등의 단위를 명시적으로 표기.
- 수치 축: 정확한 단위를 함께 제공하여 이해도를 높임.

## 데이터 라벨 규격
- 숫자 표현: 2자리 이상의 숫자는 모두 표현하도록 함 (예: 10, 50) 대신 10, 50으로 표기.
- 위치: 차트 내에서 핵심 데이터를 명확히 보여주도록 최적화.

이 규격은 PPT 데이터 시각화의 일관성과 전문성을 보장하기 위해 마련되었습니다. 이를 준수하면 고객에게 효과적인 정보 전달을 할 수 있습니다.
