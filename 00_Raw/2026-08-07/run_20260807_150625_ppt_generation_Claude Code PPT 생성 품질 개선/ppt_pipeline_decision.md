# PPT 생성 파이프라인 — 회의 결정문

작성: 윤서진(개발본부장, 진행) · 보완: 정도현(COO, 검수 반려 6·7번 반영)

## 결론 한 문단

PPT가 밋밋했던 원인은 도구가 아니라 규격의 부재였다. 최종 산출물은 고객이 수정할 수 있는 `.pptx`로 고정하고 python-pptx로 조립하되, 편집 대상이 아닌 표지·섹션 구분만 HTML/CSS 렌더 이미지로 얹는다. 화려함은 컬러·타이포·그리드를 숫자로 못 박아 코드로 강제하고, 풍성함은 슬라이드마다 답할 질문 하나와 시각 요소 최소 1개를 규칙으로 세워 담보한다. 출처 없는 수치는 라벨을 붙여 통과시키지 않고 발행을 차단한다. 이번 회의는 방향 확정까지이며 구축은 개발본부가 이어받는다.

## 확정 사항

| # | 항목 | 결정 | 근거 |
|---|---|---|---|
| 1 | 기술 스택 | **python-pptx 단독 기본.** HTML/CSS 렌더 이미지는 표지·섹션 구분에만 부분 적용 | 최종 요건이 "편집 가능한 .pptx"라 네이티브 개체로 넣어야 한다. Marp/Reveal.js는 .pptx 산출 불가로 배제 |
| 2 | 네이티브/이미지 경계 | **고객이 문구를 고칠 가능성이 있는 슬라이드는 네이티브, 고칠 일이 없는 장식 슬라이드만 이미지** | 본문을 이미지로 얹으면 고객사명 하나 고치는 데도 우리에게 재요청해야 한다 |
| 3 | 디자인 규격 | 16:9 (13.333in × 7.5in), 여백 상 0.6in / 하 0.5in / 좌우 0.8in, 12열 그리드. 컬러 Primary `#3498db` · Accent `#f1c40f` · 배경 `#ffffff` · 본문 `#2c3e50`. 제목 Montserrat Bold 40pt, 본문 Roboto Regular 16pt. 렌더 이미지는 1920×1080px @96dpi로 생성 | 일관성이 곧 화려함이다. 슬라이드 자체는 픽셀이 아니라 인치로 규정한다(.pptx는 픽셀 단위가 아니다). 픽셀은 얹을 이미지에만 쓴다 |
| 4 | 비주얼 에셋 | 글자 없는 배경·무드는 로컬 ComfyUI+Flux(무료), 한글 텍스트 그래픽은 HTML/CSS 렌더. 이미지 1장 200KB 권장·500KB 상한, 파일 전체 8MB 한도 | Flux는 한글 글자를 못 쓴다. 용량 두 기준은 층위가 달라 구분해 적용 |
| 5 | 데이터·차트 | 차트는 JSON으로 받아 네이티브 차트로 삽입. `source`·`asOf` 필수 | 출처 없는 수치를 지어내지 않는 것이 회사 규칙이다 |
| 6 | 품질 게이트 | 출처 없는 수치·차트, .pptx 구조 파손, 시각 요소 0개 슬라이드는 **P0 발행 차단**. 규격·분량 위반은 P1 자동 보정 | `(예시)`·`(불명)` 라벨을 달아 통과시키는 경로는 두지 않는다. 라벨링은 규칙 준수가 아니라 우회다 |
| 7 | 1순위 활용처 | **쇼츠 제작 자동화 납품 B2B 제안서** (12장) | 매출에 가장 가깝고 반복 사용 빈도가 가장 높다. 보고자료·투자자료는 여기서 파생 |

## 파이프라인 단계

1. **입력** — 고객사명·업종·요구사항을 마크다운으로 받는다.
2. **원고 생성** — 슬라이드 단위로 쪼개고 각 장이 답할 질문과 레이아웃 유형을 결정한다.
3. **에셋 준비** — 표지·섹션 구분은 HTML/CSS로 렌더해 PNG로, 배경은 ComfyUI로 생성한다.
4. **조립** — python-pptx로 슬라이드를 만든다. 장식 슬라이드만 PNG 전면 배치, 나머지는 네이티브 개체.
5. **검사·출력** — 품질 게이트를 돌려 P0 위반이 없으면 `.pptx`로 저장한다.

## 후속 작업 (개발본부 이관)

| # | 작업 | 담당 | 산출물 | 선행조건 |
|---|---|---|---|---|
| 1 | 조립 파이프라인 구현 (`build_deck.py`) | 이도연 | 마크다운 입력 → `.pptx` 출력이 도는 스크립트 | 레이아웃 유형 5종 확정 |
| 2 | 디자인 시스템 코드화 (레이아웃 5종·팔레트·그리드) | 오세린 | 슬라이드 마스터와 레이아웃 함수 | 확정사항 3번 |
| 3 | 비주얼 에셋 자동 조달 연결 | 강시우 | 프롬프트 추출 → 생성 → 선별 → 삽입 경로 | 1번 파이프라인 골격 |
| 4 | 품질 게이트 스크립트 구현 | 박지원 | P0/P1 검사기와 반려 리포트 | 1번 산출물이 나와야 검사 대상이 생김 |
| 5 | 전체 리뷰·통합 | 윤서진 | 1~4 통합 후 제안서 1건 실제 산출 | 1~4 완료 |

진행자는 총괄·리뷰를 맡고 구현은 담당자가 한다. 후속 작업 전체는 cto-seojin 라인으로 이관한다.

## 대표 결재 결과 (2026-08-07)

두 건 모두 결재 완료됐다. 추가로 물을 것 없이 아래 값으로 진행한다.

| 안건 | 결재 결과 | 후속 반영 |
|---|---|---|
| 제안서 템플릿을 1순위로 착수할지 | **승인** — 쇼츠 납품 B2B 제안서 템플릿부터 착수 | 후속 작업 1~5번을 이 템플릿 기준으로 진행 |
| 유료 스톡 이미지를 쓸지, 무료 소스만 쓸지 | **비승인 — 무료 소스로 확정** | 인물 사진이 필요한 구성은 쓰지 않는다. 임시 대응이 아니라 확정 방침이다 |

아직 대표 판단이 나오지 않은 것은 아이콘 유료 등급 전환 한 건이다. 인물 사진 건과 별개 사안이므로 위 결재를 근거로 임의 처리하지 않는다.

## 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 렌더 이미지가 본문까지 침범 | 고객이 못 고치는 제안서가 되어 수정 요청이 우리에게 반복 유입 | 경계 규정을 코드로 강제 — 레이아웃 유형이 표지·섹션일 때만 이미지 배치 분기를 탄다 |
| 출처 없는 수치가 라벨 달고 통과 | 근거 없는 숫자가 고객에게 사실처럼 전달 | P0 차단으로 고정. 라벨링 우회 경로를 스펙에서 제거 |
| python-pptx로 디자인을 흉내 내다 코드 비대화 | 유지보수 불가 | 도형 장치는 컬러 바·오버레이로 제한, 그 이상은 렌더 이미지로 |
| 고객 PC에 폰트 없음 | 레이아웃 깨짐 | 폰트 임베드 또는 대체 폰트 줄바꿈 사전 확인 |

## 다음 점검

- 1번 파이프라인이 제안서 1건을 실제로 산출한 시점에 품질 게이트를 걸어 P0 위반 0건인지 확인한다.
- 기술 스택은 확정이다. Marp/Reveal.js 재논의는 하지 않는다 — `.pptx` 요건으로 이미 배제했다.
