# 사주 앱 QA 테스트 플랜

## 자동화 우선순위 5개 시나리오
1.  **[Playwright] 유효 토큰으로 콘텐츠 접근 성공:** `/api/v1/content` 호출 전, `user_token`의 만료 시간과 권한 레벨(Paid/Free)을 모두 검증하는 어서션 필요.
2.  **[Vitest] 만료된 토큰 재사용 시도 방어:** 401 Unauthorized 응답 코드가 반환되며, 클라이언트 측에 정확한 '토큰 만료' 안내 메시지가 표시되는지 확인.
3.  **[Playwright] 결제 실패 후 자동 재시도 로직 검증 (Idempotency):** 결제 API 호출 시 네트워크 오류 발생을 가정하여 트랜잭션 상태가 중복 기록되지 않음을 확인하는 어서션.
4.  **[Vitest] 웹훅 수신 누락 시 데이터 정합성 체크:** 비동기 백그라운드 작업(예: 포인트 적립)이 일정 시간 내에 완료되지 않았을 때, 최종 DB 상태 플래그가 'Pending'에서 벗어나지 않는지 검증.
5.  **[Playwright] 권한 경계 조건 테스트 (Boundary Test):** 유료 콘텐츠 접근 시도 전, 사용자가 결제 페이지로 정확히 리디렉션되며, 해당 페이지의 UI 요소(CTA 버튼)가 활성화되는지 확인.

## 결제 분쟁 시뮬레이션 3개
*   **Chargeback 발생:** PayPal Webhook을 통해 `chargeback_event` 수신 -> 시스템이 자동으로 트랜잭션 상태를 'Disputed'로 변경하고, 해당 플래그 기반으로 콘텐츠 접근 권한을 즉시 회수하는지 확인.
*   **Sandbox 환불 (Partial Refund):** 결제 금액의 50%만 API 호출로 부분 환불 처리 -> 시스템이 기록하는 `refund_amount`와 최종 트랜잭션 상태가 정확히 업데이트되는지 검증.
*   **Webhook 누락 재발송:** 성공 트랜잭션 직후, 웹훅(예: 포인트 적립)이 3회 연속으로 수신되지 않을 경우 -> 시스템 내부 로직(Cron Job/Queue Retry)이 재시도하며 최종적으로 데이터 정합성을 맞추는지 테스트.

## 결제 흐름 가장 위험한 실패 지점 3개 + 방어 코드 위치
1.  **상태 플래그 비동기 업데이트 누락:** (위험 지점: 서버 레벨 DB 트랜잭션) `Payment Success` API 응답 후, 권한 상태(`is_premium`)를 업데이트하는 로직이 실패할 경우, 사용자에게는 성공했으나 시스템은 이를 인지하지 못함.
2.  **토큰 유효성 검증 누락:** (위험 지점: 모든 백엔드 엔드포인트 진입점) 클라이언트가 전송한 토큰의 만료 여부나 무결성을 Gateway 레벨에서 강제적으로 재검증하는 로직이 필수적임.
3.  **동시성 트랜잭션 충돌:** (위험 지점: 결제 및 포인트 적립 API 호출) 두 개의 요청(예: 구매와 쿠폰 적용)이 거의 동시에 들어왔을 때, 데이터 Race Condition으로 인해 한쪽의 처리가 덮어쓰여지는지 확인해야 함.

## E2E 환경
*   **CI/GitHub Actions:** 전체 스위트 테스트 실행 (주요 Path + 실패 케이스). 빌드 성공 시 자동 리포팅 필수.
*   **로컬 개발 환경:** 신규 기능 및 복잡한 비즈니스 로직(예: 할인 쿠폰 조합)에 대한 Smoke Test 전용으로 활용.
*   **Sandbox PayPal:** 모든 결제 게이트웨이 연동 테스트의 최종 검증 장소. **Production Key 사용 금지.**
