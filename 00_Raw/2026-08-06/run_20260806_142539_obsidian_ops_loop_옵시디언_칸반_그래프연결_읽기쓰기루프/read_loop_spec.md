# 읽기 루프 스펙 (Read-Write Loop)

## 문제 정의 한 줄
현재 볼트는 '쓰기 전용'으로 운영되며, 아무도 내용을 다시 읽지 않아 개선이 필요하다.

## 루프 1 — 작업 시작 전 조회 (Pre-read)
### 트리거
- archive-head-haru가 매일 두 번(13:48 / 03:44 cron) 일지를 작성할 때
### 조회 순서
1. '70 Record/YYYY-MM-DD.md' 파일에서 오늘의 업무일지를 확인한다.
2. '09 업무 가이드/모아 시스템 가이드.md'와 '모아 자산 목록.md'에서 필요한 정보를 찾아본다.
3. '91 Images' 디렉토리에서 관련 이미지 파일을 검사한다.
### 검색 키 설계
- 태그: #업무일지 / 백링크: [[70 Record/YYYY-MM-DD]]
- 이유: 이들 요소는 일지를 작성할 때 중요한 정보와 링크를 제공하기 때문
### 읽은 결과를 어디에 반영하나
- '01 Dashboard/TODO.Kanban.md' 파일의 카드 상태를 확인하고, 필요하다면 '02 Projects' 폴더 내의 프로젝트 허브 노트를 업데이트한다.

## 루프 2 — 주간 회고 (Weekly retro)
### 시각
- 매주 월요일 오전 7:30, 전략 리포트 직후
### 지난 7일 일지에서 뽑는 섹션
| 뽑을 섹션 | 왜 |
|---|---|
| 막힌 것 / 진행 중 | 최근 주 동안 마크다운 파일에서 작업이 진행되지 않은 프로젝트와 막힌 점을 확인하기 위함 |
| 클로 실수 표기 | 이전 주의 실수를 회고하고, 반복되지 않도록 개선 방안을 찾는 데 필요한 정보 제공 |
### 회고 산출물 경로
- '72 TODO Finish/' 디렉토리에 주간 회고 문서를 작성한다.

## 루프 3 — 반복 실수 차단
- 같은 실수가 2회 이상 나오면, qa-lead-jian이 형에게 알려주고, 해당 프로젝트 허브 노트에서 실수 내용을 기록하고, 다음 주 회고 시 개선 방안을 제시한다.

## 측정 지표
| 지표 | 정의 | 목표 |
|---|---|---|
| pre-read 실행률 | 매일 두 번 일지를 작성할 때마다 루프 1이 정확하게 수행되는 비율 | 100% |
| 주간 회고 완료율 | 매주 월요일 오전 7:30 전략 리포트 직후에 주간 회고 문서가 작성되는 비율 | 100% |
| 클로 실수 반복 차단률 | 같은 실수가 2회 이상 발생하는 프로젝트가 없는 비율 | 95% |

## 실패 모드
- 읽기 루프가 형식적으로만 도는 경우, archive-head-haru의 일지 작성 시간인 매일 13:48 / 03:44에 '70 Record/YYYY-MM-DD.md' 파일을 확인하지 않으면, '01 Dashboard/TODO.Kanban.md' 파일의 카드 상태가 정확히 갱신되지 않을 수 있다. 예를 들어 k-saju 프로젝트에서 작업이 멈춘 상태인데, archive-head-haru가 이를 확인하지 않고 일지를 작성하면, k-saju 프로젝트 허브 노트도 업데이트되지 않아 실수를 반복하게 될 수 있다.
