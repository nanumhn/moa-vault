# 기록 무결성 게이트

## 게이트 위치
- 일지 커밋 전인가

## 게이트 1 — '완료' 판정 체크리스트
| # | 검사 | 통과 조건 | 증거 형태 |
|---|---|---|---|
| 1 | 산출물 실재 | 완료된 카드의 YAML 프론트매터 `status` 필드가 'done'으로 설정되어 있어야 한다. | 파일 경로 / 커밋 해시 |
| 2 | 라이브 확인 | 완료된 카드의 내용은 실제로 완료되었음을 보여주는 증거(커밋 해시 / URL 재조회 값)가 있어야 한다. | URL 재조회 값 |
| 3 | 추가 검증 | 프론트매터 `estimate` 필드로 지정한 기간 동안 일지에 관련 업무일지가 작성되어 있어야 한다. | 일지 내용 확인 |
| 4 | 품질 검수 | QA-LEAD-JIAN이 완료 판정을 검수하여 #drift-alert 태그 없음으로 통과해야 한다. | QA 검수 결과 |
| 5 | 저장 경로 | 완료된 카드는 '72 TODO Finish/' 하위 폴더에 옮겨져야 한다. | 파일 경로 확인 |

## 게이트 2 — 백링크 무결성
| 검사 | 통과 조건 | 확인 방법 |
|---|---|---|
| 깨진 링크 | 0개 | '01 Dashboard' 폴더의 칸반 보드를 기준으로, 일지에 포함된 모든 링크가 존재해야 한다. 예: [[모아 시스템 가이드]] / [[72 TODO Finish/]] | 깨진 링크 확인 |
| 억지 링크 | 0개 | 백링크는 실제 연결된 노트로만 작성되어 있어야 하며, 임의의 노트를 참조하지 않아야 한다. 예: [[없는 노트]] | 백링크 생성 내역 |

## 자동 백링크의 위험과 차단 규칙
1. **위험**: 백링크가 자동으로 생성되면, 잘못된 링크가 생성되어 검색 엔진에서 지정된 노트를 찾지 못하게 될 수 있다.
   - **차단 규칙**: 백링크는 항상 합법적이고 실제 존재하는 노트로만 작성되어야 하며, 자동화된 백링크 생성은 금지된다.

2. **위험**: 자동 백링크가 잘못되면, 검색 결과가 혼란스러워질 수 있고 사용자에게 오류를 일으킬 수 있다.
   - **차단 규칙**: 백링크는 합법적이고 실제 존재하는 노트로만 작성되어야 하며, 자동화된 백링크 생성은 금지된다.

## 반려 경로
| 불합격 유형 | 반려 대상 | 요구 사항 | 재검 기한 |
|---|---|---|---|
| 완료 판정 미달 | status 필드가 'done'으로 설정되지 않은 카드 | status 필드를 확인하고 수정하여 다시 검수 | 1일 |
| 증거 부족 | URL 재조회 값이 제공되지 않거나, 일지에 관련 업무일지가 작성되지 않았음 | 필요한 증거를 추가하여 다시 검수 | 1일 |
| 백링크 문제 | 깨진 링크 / 억지 링크 발견 | 백링크를 확인하고 수정하여 다시 검수 | 2일 |
| QA 검수 실패 | QA-LEAD-JIAN의 #drift-alert 태그가 발견됨 | QA 검수 결과를 확인하고 수정하여 다시 검수 | 1일 |
| 저장 경로 문제 | 완료된 카드가 올바른 폴더에 옮겨지지 않음 | 카드를 올바른 폴더로 이동하여 다시 검수 | 2일 |

## 게이트가 검사하지 않는 것 (경계)
- 파일 이름 형식과 동기화
- 칸반 보드의 컬럼 상태 변경 로직
- 일지 작성 시 양식 확인
- 프론트매터 스키마 확장
