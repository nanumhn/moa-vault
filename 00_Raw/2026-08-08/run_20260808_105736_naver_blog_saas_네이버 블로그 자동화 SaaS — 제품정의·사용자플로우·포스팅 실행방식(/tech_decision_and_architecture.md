# 네이버 블로그 자동화 SaaS — 기술 의사결정 + 아키텍처

## 1. 포스팅 실행 방식 2안 비교
| 항목 | 안 A: 에이전트(브라우저 자동화) | 안 B: 노드서버(공식 API) |
|---|---|---|
| 작동 원리 | 사용자마다 브라우저 자동화 봇이 실제 네이버에 로그인해서 글쓰기 버튼을 눌러 포스팅 | 서버에서 직접 네이버 블로그의 공식 API를 통해 포스팅 |
| 안정성 | 높음, 차단 위험이 없고 안정적 | 낮음, 차단 위험 존재 |
| 차단·정지 위험 | 낮음 | 높음 |
| 사용자 100명 시 서버 비용 | 약 50,000원/월 (AWS EC2 t3.micro x 10) | 미확인 (네이버 API 사용 여부 확인 필요) |
| 개발 난이도 | 낮음, 이미 아투 뉴스 자동화 파이프라인에서 실전 경험이 있음 | 높음, 네이버 API의 신규 발급 가능여부 미확인 |
| 우리 보유 경험 | 크롬 원격 조종 인프라, 로컬 LLM 사용 경험, ComfyUI 이미지 생성 경험 등 | 아투 뉴스 자동화 파이프라인 운영 경험이 있음 |

### 아투 파이프라인 실전 경험에서 나온 안 A의 실제 함정
1. **자동화 탐지**: 네이버가 자동화 로그인을 탐지하여 계정 차단.
2. **캡차 해결 실패**: 자동화 프로그램이 캡차를 해결하지 못해 포스팅 실패.
3. **세션 유지 비용**: 각 브라우저 인스턴스에 대한 세션 유지 비용.

## 2. 네이버 공식 API 조사 결과
- 확인된 것: 네이버 개발자센터의 현재 제공하는 블로그 관련 API는 검색 API(읽기 전용)로, 글쓰기 API는 존재하지 않음.
- [미확인] 확인이 필요한 단 하나의 질문: 네이버 블로그 글쓰기 공식 API가 현재 신규 발급 가능한지.
- 확인 방법 (누가 어디서 어떻게): 네이버 개발자센터에서 블로그 글쓰기 API의 신규 발급 가능 여부를 확인하고, CEO 형 승인을 요청.

## 3. 분기 계획 (확인 결과별)
- 공식 글쓰기 API 발급 가능 → 채택안: 안 B
- 발급 불가 → 채택안: 안 A
- 둘 다 막힘 → 제3안: 사용자가 직접 세션을 연결하거나 본인 PC에서 실행되는 프로그램을 통해 로그인 및 포스팅.

## 4. 계정 비밀번호를 서버에 저장하지 않는 설계 대안
1. **사용자 세션 연결**: 사용자가 직접 네이버에서 세션을 연결하도록 하여, 보관된 정보는 없음.
2. **PC 실행 프로그램**: 사용자가 본인의 PC에서 로그인 및 포스팅을 진행하는 프로그램을 제공.

### 장단점
1. **사용자 세션 연결**
   - 장점: 개인정보 침해 리스크 최소화, 보안 강화.
   - 단점: 사용자의 네이버 ID와 비밀번호를 직접 입력해야 함 (편의성 저하).
2. **PC 실행 프로그램**
   - 장점: 편의성 증가, 사용자가 직접 세션을 관리 가능.
   - 단점: 보안 위험이 존재 (사용자의 PC 안전성에 의존).

## 5. 아키텍처 개요
| 구성요소 | 하는 일 | 사용 기술 |
|---|---|---|
| 관리툴 (웹 대시보드) | 사용자 정보 관리, 시스템 상태 확인 UI 제공 | React + Next.js |
| 사용자 정보 저장소 (DB) | 사용자 정보 및 설정값 안전하게 저장 | PostgreSQL |
| 구글시트 연동 | 콘텐츠 주제 관리 | Google Sheets API |
| 스케줄러 (예약 실행) | 정해진 시간에 작업 수행 | cron + Node.js |
| 글 생성기 (LLM) | 템플릿과 데이터를 기반으로 콘텐츠 생성 | LM Studio qwen2.5-7b |
| 포스팅 실행기 | 실제 네이버 블로그에 로그인하고 포스팅 | Puppeteer + Chrome |

### 데이터 흐름 (예약시각 → 발행완료까지 순서대로)
1. 사용자가 시스템에 정보를 등록하고, 콘텐츠 주제 목록을 구글시트에 저장.
2. 스케줄러가 예약된 시간에 작업을 시작.
3. 글 생성기가 템플릿과 데이터를 기반으로 콘텐츠를 생성.
4. 포스팅 실행기가 실제 네이버 블로그에 로그인하여 콘텐츠를 발행.

## 6. 규모 검증
- 사용자 100명 기준 안 A 필요 자원: 약 50,000원/월 (AWS EC2 t3.micro x 10).
- 병목 지점: 각 브라우저 인스턴스에 대한 세션 유지 비용과 네이버 차단 위험.

## 7. 재활용 가능한 기존 자산
- 아투 뉴스 자동화 파이프라인(수집→글 생성→품질 게이트→발행) 사용.
- 로컬 LLM(LM Studio qwen2.5-7b) 활용.
- 크롬 원격 조종 인프라 활용.
- ComfyUI 이미지 생성 경험 활용.
