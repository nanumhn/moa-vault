# 구독 인프ra 기술 설계 (로그인 · 마이페이지 · 데일리카드)

## 로그인/인증 최종 권고 (방식 + 근거 + 외부SaaS + 월비용)
- **방식**: Google OAuth
- **근거**: 코드 복잡성을 줄이고 사용자 경험을 향상시킬 수 있기 때문.
- **외부SaaS**: NextAuth와 Google OAuth
- **월비용**: 약 $10 (NextAuth) + 무료 (Google OAuth)

## 마이페이지 구성 (구독상태/결제내역/리포트보관/취소/설정)
- **구독 상태**
  - 활성/비활성 구분
- **결제 내역**
  - 구독 시작일, 만료일, 결제 수단 등
- **데일리 카드 생성 여부**
  - 사용자 선택에 따라 보관 가능
- **취소 옵션**
  - 구독 취소 기능 제공
- **설정**
  - 이메일 알림 설정

## 데일리 카드 생성 방식 (크론 vs 온디맨드, 콘텐츠 생성)
- **방식**: 크론 스케줄러 사용
- **근거**: 일정한 주기에 맞춰 데일리를 자동으로 생성하며, 시간적 비용을 줄일 수 있기 때문.

## DB 스키마 추가분 (필요 시)
- **사용자 ID**
- **구독 상태 (활성/비활성)**
- **결제 내역 (구독 시작일, 만료일, 결제 수단 등)**
- **마지막 로그인 일시**

## 구현 단계(Phase) + 우선순위 + 대략 인일
| Phase | 작업 | 우선순위 | 인일 |
|---|---|---|---|
| 1 | Google OAuth 로그인 구현 | 최우선 | 2 |
| 2 | 마이페이지 기본 기능 구현 (구독 상태, 결제 내역) | 중간 | 3 |
| 3 | 데일리 카드 생성 및 사용기능 구현 | 후순위 | 4 |
